# 错误与空值契约（P2）

> 面向"这段代码该返回什么"的决策文档。依据：`docs/Leno真实项目可用性评估_2026-11-08.md`
> §2.8 / §4.5.1 的统计（**8 种错误表达、4 类空值哨兵**），以及 2026-11-09 的落地
> （`import "Result"` 模块 + SQLite NULL 语义）。
>
> 一句话：**失败用 `Result[T]`，缺值用 `Option[T]`，进程内判空继续用 `T?`；SQL 的 NULL 永远是 `null`。**

---

## 1. 修前是什么样（问题）

| 错误表达 | 出处 | 调用方要做什么 |
|---|---|---|
| `Dict{ok, err}` | LenoSqlite `execWithErr` | 取 `_str(d["err"])` 判空 |
| `bool` | LenoFS / LenoCsv 若干 | 拿不到**原因** |
| `int -1` / `rc` | LenoSqlite `exec/step`、LenoDir | 要背 SQLite 常量 |
| typed `Result` struct | LenoWeb `web_generic`（**已删**） | 只在 Web 里有，别处没有 |
| `error` 字段 | LenoHTTP `Response` | 与 `ok()` 配合，各自实现 |
| `throw` | Aria / LenoWorkBuddy | `catch e` 只能打日志 |
| `Result[T]`（自制） | 各项目 | 字段名 / 成功判据各不同 |
| `Response.ok()` | LenoHTTP | 只适用 HTTP |

空值同理：`null`、`""`、`0`、`[]` 四种哨兵混用，最典型的是 **SQLite 把 NULL 压成
`""` / `0`**（`column_text(NULL)` ⇒ `""`），于是"这列没有值"和"这列的值就是空串"永久分不清。

## 2. 修后：一套形态

```leno
import "Result" as res
use res.(Result, Option)
```

### 2.1 `Result[T]`

| 字段 | 含义 |
|---|---|
| `bool ok` | **唯一**成功判据（不要用 `code == 0`） |
| `int code` | `ErrCode` 之一：`INVALID_ARG / NOT_FOUND / PARSE / IO / NET / DB / AUTH / CONFLICT / UNSUPPORTED / INTERNAL` |
| `string msg` | 给人看的一句话（成功时为空） |
| `T val` | 成功时的值（**失败时无意义，不要读**） |

方法：`isOk / isErr / get / unwrap / orElse / errName / errText`。
函数：`ok / err / errText / mapResult / flatMap`。

### 2.2 `Option[T]`

`some / val` + `isSome / isNone / get / unwrap / orElse`；函数 `some / none / mapOption`。

**与 `T?` 的分工**：函数内部的临时判空继续用 `T?`（零成本）；**跨模块边界**要表达
"可能没有值"就用 `Option[T]` —— 它能放进 `Result`、数组、`Dict`，且不会与 `null` 混成一体。

### 2.3 严格解析

`res.parseInt` / `res.parseFloat` 取代 `_int` / `_int_or` / `as int` 三套不一致语义：

```leno
res.parseInt("42").val        // 42
res.parseInt(" 42").isErr()   // true —— 严格，不替你去空格
res.parseInt("12a").errText() // "PARSE: 不是整数（含非数字字符）：12a"
```

## 3. 迁移对照（旧写法 → 新写法）

| 旧写法 | 新写法 |
|---|---|
| `Dict d = f(); if _str(d["err"]) != "" { ... }` | `Result[T] r = f(); if r.isErr() { ... r.code ... }` |
| `bool ok = f(); if not ok { ... }` | `Result[T]`，`code` 说明原因 |
| `int rc = ...; if rc != SQLITE_OK` | 保留（SQLite 原生码），但**新 API 不许再返回裸 rc** |
| `if x == "" { 缺值 }` | `Option[T]` 或 `x is null` 判 |
| `int n = _int_or(s, 0)` | `res.parseInt(s).orElse(0)`（默认值写在调用点） |
| `throw "INVALID_FORMAT"` | `res.err[T](res.ErrCode.PARSE, "...")`；`throw` 只留给"程序 bug" |
| SQLite `column_text(NULL)` ⇒ `""` | `column_is_null(i)` / `column_value(i)` ⇒ `null` |

## 4. SQLite NULL 语义（2026-11-09 起）

```leno
stmt.forEach(func(Statement s): bool {
    if s.column_is_null(2) { /* 这一格就是 NULL */ }
    var v = s.column_value(2)      // null / int / float / string / Ptr(BLOB)
    return true
})
```

`queryAll(path, sql)` 同步改了：INTEGER ⇒ `int`（不再是 `"123"`）、FLOAT ⇒ `float`、
NULL ⇒ `null`（不再是 `""`）、BLOB ⇒ 字节数。**仓库内零调用方**，改语义不打断任何项目。

> `column_text` / `column_int` / `column_double` **保留**：给"已确认非空"的热路径省一次分支，
> 但**新代码应优先 `column_value`** —— 否则 NULL 又会悄悄变成 `0`。

## 5. 还没做的（诚实清单）

- 20 个模块的老 API **没有**逐个改成 `Result`（`FS` 的 `bool`、`CSV` 的 `Dict{ok}`……）。
  本次只做了"**形态层 + SQLite NULL**"，其余按需迁移，避免一次性打断四个项目的调用点。
- HTTP `Response.ok()` 与 `Result` 并存：HTTP 那条是**协议层**结果（含状态码/头），
  不是"操作失败"，短期不动。
- 错误码没有编译期穷尽检查（`switch code` 漏分支不报错）。
- `Result[T]` 目前不能带"多值成功"（要两个值就包一层 struct）。
