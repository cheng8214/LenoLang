## 一、问题定式

语义性数据（**常量值**、**类型种类**、**符号归属**、**字面量集合**）在编译流程里有多个
计算点；这些点各自实现，靠注释/约定保持同步。一旦漂移，症状几乎总是
**静默错值**，而且常在半个文件之外才爆发。

信条：**同一件语义事实，只允许有一个实现者，其余都是"读"它。**

## 三、收敛顺序（建议，先立防线、再动结构）

### Phase 0：立防线（不改结构，收益立竿见影）

1. **把「三路径相等」扩成语料级差分测试**：遍历语料里所有 `export enum`，比对
   `同模块 == use 导入 == 模块限定`，不等即失败。
   雏形已有：`assert/test_enum_value_consistency.leno`（含 `BIN = 0b1010`）。把它从"一个用例"扩成"扫全部"。
2. **版本号集中登记**：三个缓存版本宏放在一处文档表格里，写明各自"为什么升"。
   并行会话/多机协作时，版本号是共享资源 —— 改前先 `git fetch` 看远端动没动同一处。

### Phase 1：把「值」收敛到一处（对应 S1 / S3 / S4）

1. 扫描器的 enum 记录先改成「名字 + **表达式原文**」（只加字段、不改行为，缓存 bump 一次）。
2. 需要值时调用**真解析器**（临时构造 `Lexer/Parser` 指向那段短表达式 → 表达式解析入口
   （`parse_expression` 或同层入口）→ `eval_const_expr`，并按现有机制设置成员引用上下文
   `g_enum_member_names/values`）。
3. 删掉 `sym_table_enum_expr.inc`。**这一步做完，"求值对齐"这件事永久消失。**
   - 备选路线：值一律取自模块**编译产物**（`.lenomc`/symc），扫描器只负责名字与形状。
   - 词汇表纪律：**字面量/运算符集合以词法器为唯一来源**，扫描器不得"多支持"
     （`0b` 那次正是扫描器比解析器更全，立刻就不一致）。

### Phase 2：把「类型」收敛到一处（对应 S2）

四张类型表加**模块维度**（key = 模块 + 名字），跨模块查找必须带模块名；
`semantic_type.c` 里"当前文件 enum 访问"那段注释与实现一并对齐。

### Phase 3：把「测试口径」统一（对应 S7）

加 `// EXPECT_ERROR: <文案/行号>` 约定或 `assert_compile_error()` 内置，
诊断类用例不再各自 `_exec`。

## 四、今天踩过的坑（别重复）

1. **手写扫描器的"跳过分隔符"必须在成员循环内部**：一行内用 `;` 分隔
   （`export enum Color { red = 100; green = 200; blue = 300 }`）时，若放在循环外，
   `;` 无人消费、成员名读不出来（`m_len == 0`）就原地打转 → **死循环**。
   护栏用例：`assert/test_enum_use_alias.leno`（其模块正是这种一行写法）。
2. **改"会烙进产物"的东西必须 bump 缓存版本**：求值语义、字面量集合、opcode 集合
   都会写进 `.lenb` / `.lenomc` / `.lenosymc`，三个版本号要一起看。
3. **验证时先关缓存**（`LENO_NO_CACHE=1`）：否则命中旧缓存根本进不到语义阶段，
   会得到"只有 1 行输出"这种假象（§8.49 记过一次）。
4. **"扫描器比解析器更正确"也是 bug**：单一来源的意义是**一致**，不是"谁更对"。
   `0b` 那次若只改扫描器去迁就解析器，就是把静默错值固化下来。
5. **扫描器要为"读不出东西"留后路**：手写扫描遇到不认识的构造时，必须前进
   （消费至少一个字符）或明确失败，绝不能原地重试。

## 五、验证手段（照抄今天的做法）

- **三路径探针**：同模块 / `use` 导入 / 模块限定三值互等；**外加绝对值断言**
  （否则"三处一致地错"拦不住）。
- **变异验证**：把修复回退，用例必须失败 —— 证明断言不是空转。
- **冷缓存验证**：`LENO_NO_CACHE=1` 跑一遍全量（覆盖扫描器路径），再热缓存跑一遍
  （覆盖缓存读写往返）。
