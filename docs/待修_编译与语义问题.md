## 1. `var` 接收可空返回值时，被推断成非可空

**状态**：待修（2026-10-28 记录）

**现象**：函数声明返回 `Widget?`（可空接口），用 `var` 接收后，`!= null` 判断**恒为真**：

```leno
// 声明
pri func(int, int, float, float): Widget? cellBuilder

// 用法（错误示范）
var ucw = cellBuilder(ri, c, cw, rowH)   // ← 被推断成 Widget（非可空）
if ucw != null {                          // ← 恒真
    ucw.render(r)
    continue                              // ← 返回 null 时也走进来，后面的内建绘制被跳过
}

// 正确写法（当前绕过）
Widget? ucw = cellBuilder(ri, c, cw, rowH)
if ucw != null { ... }
```

**最小复现**：`Table.set_cell_builder` 的回调在某一列返回 `null`。
现象是**该列整列不绘制**（本应回退到内建文本）。

**影响面**：所有"回调可选返回控件/对象"的 API。编译器不报错、运行时静默错，
很难定位（本次排查花了约 20 分钟）。

**建议修法**（择一）：
1. `var` 推断时**保留可空性**（跟随返回值类型）；
2. 或者对"可空赋给非可空"给出**警告**（至少能看见）；
3. 或者禁止 `var` 接收可空返回值，强制显式标注。

## 2. 全局文本替换类重构没有编译期保护（工程问题，非语言 bug）

**状态**：备忘

批量把 `xxx(` 重命名成 `mod.xxx(` 时，用 `String.Replace` 会**命中字符串字面量与
其它上下文**。本次出现过：
- 替换 `"resizable",` 时误改到 `opts.get("resizable", true)` → 变成
  `opts.get("radius", "resizable", true)`，报"参数过多 / 类型不匹配"。

**规避**：批量替换带引号的片段时，必须加更长的上下文（含 `opts.get(` 前缀），
或者先 `--check` 再逐条看错误行号。

## 3. 成员方法不能直接当函数值用

**状态**：待修 / 至少应给出明确报错（2026-10-28 记录）

**现象**：把同一个 struct 里的成员方法赋给一个函数类型字段，报 **"未定义的变量"**
（不是"方法不能作为值"这种能看懂的提示）：

```leno
// struct 内
pri func track_row_like(Song sg, Button b) { ... }

// 调用处（报错：未定义的变量: track_row_like）
hk.onTrack = track_row_like

// 当前绕过：lambda 包一层
hk.onTrack = func(Song sg2, Button b) { track_row_like(sg2, b) }
```

**注意**：定义在后面的方法尤其明显（本例定义在 2267 行、引用在 999 行）。
建议编译器区分两种情况给提示：
- 真的没这个名字 → "未定义的变量"；
- 是方法但被当成值取 → "成员方法不能作为函数值，请用 lambda 包装（或 `self.xxx`）"。

## 4. `Widget` 接口没有命中测试

**状态**：待增强（2026-10-28 记录）

`face Widget` 只有 `get_w/get_h/set_pos/set_size/process/render/dispose`。
在"表格单元格里放按钮"这类场景，宿主无法判断"这次点击是否落在子控件上"，
只能把事件**广播**给子控件，同时自己也处理行选择 ⇒ 点按钮会连带触发行双击。

**建议**：`face Widget` 增加 `func hit_test(float x, float y): bool`
（默认实现 = 点在 `[x, y, x+w, y+h]` 内），宿主的转发逻辑变成
"命中才转发、命中则吞掉事件"。
