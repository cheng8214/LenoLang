## M1【高】`threads.start` 的入口判据是"module 必须为空"，报错文案却说"当前文件"

**隐式契约**（源码判据 `src/module/threads/threads.c:130` 一带）：线程入口函数 `f` 必须
**不属于任何模块**——子 VM 只继承**调用方 VM** 的 globals，且把自己的 current_module_frame
置 NULL ⇒ **模块函数进不了线程函数体**。

**实测复现**（LenoMusic 拆分当天 ✓）：把 `bang_menu_worker` 搬进模块 `bang_page.leno` 后：

```
threads.start(): 线程入口必须是**当前文件**的函数 ✗ 收到的是模块 'bangpg' 里的 'bang_menu_worker'
```

两层问题：
- 文案说"**当前文件**"，实现判的是"**入口脚本**"——同一次运行里"当前文件"有好几个
  （每个被 import 的模块都是当前文件之一）⇒ 照着文案改不出对的结果；
- `threads使用指南.md` **查不到这条契约** ⇒ 模块化重构第一次起线程必撞，撞完还看不懂。

**可行解（已实测 ✓）**：宿主把 worker **当函数值**传进模块，模块里存成
`func(...):...` 字段再 `threads.start(字段, …)`——此时 `f` 仍是入口脚本的函数
（module == NULL）✓，子线程 globals 正常 ✓（探针实测 join 回值正确 ✓）。
LenoMusic 三个页面模块全部按此落地 ✓。

**修法建议（择一或全做）**：
1. **改报错文案**（最便宜）：把"当前文件"改成"**入口脚本（顶层文件）的具名全局函数**；
   被导入模块里的函数不行——模块函数拿不到子线程的 globals。模块要起线程，
   请让宿主把函数**当值传进来**（`threads.start(field, …)` 也行）"；
2. **文档补节**：`threads使用指南.md` 加"线程入口的模块限制"一节（契约 + 函数值解法 + 探针）；
3. （治本，可选）支持模块函数作入口：子 VM 按需加载该模块的 globals——代价要评估。

## M2【高】调用"函数类型字段"的返回值是 `any`（声明的返回类型没生效）

**实测复现**（探针，2026-10-11 ✓）：

```leno
// 模块里
pri func():string outdirOf
pri func outdir(): string {
    return outdirOf()        // ✗ error: [类型不匹配] 返回类型不匹配：期望 string，实际 any
}
```

哪怕字段声明是 `func():string`，**通过字段调用**的返回值在类型系统里仍是 `any`
⇒ 必须手动收窄：`var d = outdirOf()  return d as string` ✓（`as` 收窄后可用）。
普通函数调用不受影响（返回类型正常）⇒ 洞只在"函数值当字段/变量再调"这一形态。

**为什么疼**：函数值是本语言"跨模块传行为"的正路（M1 的解法就靠它）⇒ 用得越多，
这个洞越常撞；而且报错只说"实际 any"，看不出"明明声明了返回类型"。

**修法建议**：函数类型字段的调用按声明签名推返回类型（签名就在那，信息是现成的）；
顺带把 M1 的解法场景跑一遍回归（函数值 → threads.start 不受影响 ✓）。

## M3【中】`this` 不存在、自引用叫 `self`——但误用 `this` 的报错不提示

**实测**（2026-10-11 ✓，两支探针）：
- 方法里写 `return this` ⇒ `error: [未定义变量] 未定义的变量: this`（无任何提示）✗；
- 方法里写 `return self` ⇒ **完全可用** ✓：经返回的引用写字段，原对象同步变
  （引用语义，探针 `m.v = 42 ⇒ h.v == 42` ✓）——"返回自己"这件事**做得到** ✓。

所以这条的本质是**报错质量**小项：`this` 是最常见的顺手词，报"未定义变量"却不带
"是否想用 'self'？"（仓里已有同款先例：`contains()` 写错提示 `has()` ✓）。

**修法建议**：未定义变量报错对 `this` / `self` / `This` 这几个高频误拼给纠错提示；
`Leno入门教程.md`（struct 一节）补一句"方法内自引用用 `self`"。

## M4【中】模块别名与 struct 字段同名 ⇒ 静默遮蔽，报错指到别处

**实测复现**（LenoMusic 拆分当天 ✓）：入口脚本里

```leno
import "./bang_page.leno" as bang      // 模块别名
struct App { BangPage? bang = null }   // 恰好也有个字段叫 bang

// 方法里：
bang = bang.create_bang_page(...)      // ✗ 后一个 bang 被解析成"字段"
```

报错是"在字段 bang 上找不到方法 `create_bang_page`"之类——**看不出是遮蔽**
（字段把模块名遮了）⇒ 排查烧掉好几轮编译循环。改名 `as bangpg` 后当场通过 ✓。

**修法建议**：语义阶段检测"模块别名 vs 同作用域字段/变量同名"并直接报错
（哪怕只给 warning：「别名 'bang' 被同名字段遮蔽，模块成员将不可达」）——
这种冲突几乎从不合法，报出来没有误伤成本。

## M5【低】三件小摩擦（每个都吃掉一次编译循环）

| # | 摩擦 | 实测 | 建议 |
|---|---|---|---|
| 5a | **内建类型进不了 `use 模块.(…)` 批量导入**：`use SDL3.(…, Thread)` 报"期望类型名" | 2026-10-11 ✓（`Thread` 是内建类型，不是 SDL3 导出的） | 报错说清"X 是内建类型，无需 use"即可（内建类型本来就不该放进来，但报错要指路） |
| 5b | **保留字撞名无提示**：`Outer alias = o`（`alias` 是关键字）报的是普通语法错，看不出"这是保留字" | 2026-10-11 探针 ✓ | 保留字位置报错统一带一句"'alias' 是保留字，换个名字" |
| 5c | **`pri` 字段逼出成套 setter 样板**：模块工厂没法直填 `pri` 字段 ⇒ 每个都写 `set_xxx`（LenoMusic 两个页面模块各 5+ 个） | 2026-10-11 ✓ | 给 struct 工厂一点语法便利：如 `new T() { field: v, … }` 字面初始化（能直填 pri，只限"同一模块/创建表达式"），或允许同模块内工厂直填 |
