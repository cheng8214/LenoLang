## 0. 总判断

**Leno 已经跨过“能写真实产品”的门槛，但还没跨过“规模化维护”的门槛。**

正面证据是硬的：四个项目都完成打包分发；Aria 24,614 行，里面是一个真正的 HTTP 服务端（线程池 + SQLite + 鉴权 + 管理后台）；LenoMusic 有 17 个可离线运行的测试并产出 Linux 构建；WorkBuddy 有 `doctor`、离线 stub 和成体系的错误码；LenoTrae 有黄金样例回归。单文件 exe 约 10–12MB，目标机不需要装运行时（[WorkBuddy README:16](file:///d:/CLeno/LenoWorkBuddy/README.md#L16)），这条工程链路是通的。

**但成本集中在四个“边界”上，而不是语法：**

1. 数据一旦要跨线程、上表格或落盘，类型就蒸发，退回 `Array[Array[string]]` / `Dict` + `_str`；
2. 状态要么编码成魔法整数/字符串码（int `enum` 本可用，但无约定/提示），要么受限于 enum 不能带载荷，逻辑分散到多个文件；
3. 严格解析和可分类的错误没有标准类型，每个项目自己造一套 `Result`/`Parse`——标准库自己也有 8 种错误写法、4 类空值哨兵（§4.5）；
4. 模块与 VM 的实现细节（`extend` 模块级、256 字段、255 局部量）直接改写应用的架构。

关键计数：

**但这 6 个 0 需要分开看**：`build\leno.exe` 最小用例实测（见 §3.5）表明 `switch`（int/string/enum）、int `enum`、`map/filter/reduce`、用户泛型都能编译并正确运行；`face/impl` 与 `async func` **未实测**，不能据此断言可用。在已测项里，真正缺失的只有 **enum 载荷** 和 **比较器排序**。0 使用改变的是病因判断，不是语言能力判断（见 §3.6、§6）。

**标准库这一层把同一个判断放大了一倍。** `build\leno_module` 有 20 个模块、53,052 行非空 lib 代码（含空行 58,011）、663 个按“每模块单门面文件”口径统计的导出函数（若统计所有 lib 顶层 `export func` 则为 1,590）——HTTP 客户端、JSON、日志、文件遍历、表格读写都在里面，能力层是真实存在的。但四个项目 import 公共门面 `Web` **0 次**，import 它的内部文件 `web_net.leno` **37 次**；77% 的库行数不在 `run_all_tests.leno` 的可见范围内。也就是说，标准库"有能力，但没有成为标准形态"（详见 §4.5）。

> **复核（2026-11-09）**：`import "Web"` **仍是 0 次**、`web_net` **仍是 37 次**（这一条没动）。

**一句话：语言的核心表达力（含 `switch` / int `enum` / `map·filter·reduce` / 泛型）经实测是够用的；问题在"标准数据形态、标准错误形态"缺席——标准库有 20 个模块却同样没有提供这两种形态，生成侧也没有任何机制把作者推向惯用写法。最大的单点天花板仍是 8 位索引限额，已测项里真正缺失的语法只剩 enum 载荷、比较器排序和穷尽性检查（`face/impl`、`async` 未实测）。**

## 1. 哪些代码像“正常语言写出来的”

### 1.1 结构体 + 方法 + 一等函数字段：`cards.leno`

[CardSize](file:///d:/CLeno/Aria/lib/cards.leno#L33-L81) 是纯数据结构 + 方法，[CardHooks](file:///d:/CLeno/Aria/lib/cards.leno#L85-L97) 用函数字段表达可选回调，[song_card](file:///d:/CLeno/Aria/lib/cards.leno#L108-L135) 用字典传样式、用闭包挂事件：

```leno
if h.onPlay != null {
    Song s = sg
    c.on_click(func() { h.onPlay(s) })
}
```

这段没有框架味，也不需要“组件基类”。它证明 Leno 的 `struct + methods + function values + closure` 足以写出可组合的 UI 组件。这是全仓最像“正常语言”的一段。

### 1.2 数据即代码：`routes.leno`

[路由表](file:///d:/CLeno/Aria/server/routes.leno#L23-L72) 直接是一个 `Array[Dict]`，handler 是函数值，加接口只改一处：

```leno
{method: "GET",  path: "/api/square", handler: rep.api_square, auth: true},   // 广场（需登录）
```

这类 DSL 写法比手写 `if path == ...` 好得多，说明语言在“声明式配置 + 闭包”这个方向上是够用的。

### 1.3 纯逻辑分层：`LenoMusic/player.leno`

### 2.1 数据只能住在字符串数组里（最大的样板来源）

[Aria downloads.leno:446-449](file:///d:/CLeno/Aria/lib/downloads.leno#L446-L449) 自己写明了行协议：

```leno
// 为什么用行而不是 struct 数组：字段要原地更新（状态 0→1、进度 0→N），字符串行最好改
```

紧接着是 `len()` 守卫、下标读写、`_int`/`_str` 转换：[462-476](file:///d:/CLeno/Aria/lib/downloads.leno#L462-L476)、[558-602](file:///d:/CLeno/Aria/lib/downloads.leno#L558-L602)（`pause_all` / `resume_all` / `toggle_pause` 三段同构循环）。落盘时又要换成对象数组：

> `存成对象数组而不是行数组：JSON 读回来的是 Array[any]，按行下标取要反复收窄，字段名一改就静默错位` —— [604-606](file:///d:/CLeno/Aria/lib/downloads.leno#L604-L606)

> ⚠ **但引用的那句理由不成立（2026-11-09 实测）**：`downloads.leno` 的注释写
> “为什么用行而不是 struct 数组：**字段要原地更新**”。实测 `Array[struct]` **完全支持**原地更新：
>
> ```
> jobs[0].status = 1                  → 1     ✓ 原地改
> jobs[0].progress = 0.9（再改一次）   → 0.9   ✓ 不是副本
> for jobs to j { j.status = 2 }      → 22    ✓ 循环里改
> bump(Job j) { j.status = 77 }       → 77    ✓ 传参改（引用语义）
> Job j2 = jobs[1]; j2.status = 99    → 99    ✓ 取出元素再改
> type(jobs[0])                       → Job   ✓ 类型保留
> ```
>
> ⇒ “字段要原地更新”**不是**用行数组的理由。356 处行数组属于**引导缺口**（没人示范），
> 不是能力缺口 —— 真正缺的只有“记录 ↔ JSON/表格”的**自动编解码**（P1）。

## 3. 抽象能力盘点与实测复核

| 能力 | 现状 | 评价 |
|---|---|---|
| 函数/闭包 | 一等函数字段、闭包捕获、默认参数都在用 | **好**；但跨线程闭包捕获 `self` 会炸，入口必须模块级函数（[net_workers:4](file:///d:/CLeno/Aria/lib/net_workers.leno#L4-L7)） |
| 结构体 | 方法、`extend`、默认值、值语义 | **能用但痛**：256 字段上限；数组元素更新常写成“整行取出→改→写回”（[downloads:562-569](file:///d:/CLeno/Aria/lib/downloads.leno#L562-L569)）；`extend` 的 import 税 |
| 模块/导入 | `import` 文件、`import 模块`、`use` 类型 | **痛**：函数/常量不随 `use` 导入；无 re-export；循环依赖靠复制；`extend` 可见性按模块算 |
| 错误处理 | `throw`/`catch` 任意值 | **痛**：无 Result/Option、无错误类型、`catch` 常退化成打日志 |
| 泛型 | 实测可用：泛型函数 / 泛型 struct / 比较运算均通过（比较时给 `[泛型无约束]` 提醒） | **能力有、生态无**：0 用户使用属引导问题 |
| 枚举 | int 常量可用（§3.5 实测通过），无载荷、无穷尽检查 | **半能用**：常量状态够用，消息载荷不够；0 使用属引导问题 |
| 接口 `face` | 有 `face`/`impl` 语法（教程有说明） | **有能力、0 使用**：跨模块回调用 `any` + `is` 模拟（[dl_flow:101](file:///d:/CLeno/LenoMusic/dl_flow.leno#L99-L103)） |
| 集合 | `Array/Dict` + `sort`/`filter`/`map`/`reduce`（实测可用，`map` 返回 `Array[int]`） | **基本够用**：缺 comparator / 稳定排序（`lrc_sort` 手写）；0 使用属引导问题 |
| 字符串 | 切片、`take`、`find`、`join`、`format` | **够但弱**：无 `rfind`/`split` 模块函数/严格 parse；`format` 0 使用，普遍 `+` 与 `_str` |
| 并发 | `threads` + `Channel` + 线程局部存储 | **能用**：隔离 VM、`Ptr` 不能跨线程、模块 `var` 共享无锁 ⇒ 每 worker 重建 app、句柄重开（[server.leno:23-37](file:///d:/CLeno/Aria/server/server.leno#L23-L37)） |

补一刀：安全库也不完整——`LenoCrypto` 没有 PBKDF2/argon2，Aria 只能 `sha256("v1:"+salt+":"+pass)`，作者自己标注“够用但不算理想”（[server.leno:34-35](file:///d:/CLeno/Aria/server/server.leno#L34-L35)）。

**“根本没法写”的很少，但“规模一大就写不下去”的很明确：**
- >256 成员的领域模型（硬编译错误）；
- 带载荷的消息（只能 `any`/字符串数组）；
- 单函数 >255 局部量；
- 可分类的错误（只能自己造 Result）。

其余都是“能写但痛”。

### 3.5 用 `build\leno.exe` 实测：哪些是“没写”，哪些是“没有”

方法：在临时目录（`build\_probe`，用后删除）用 `leno.exe` 直接编译运行最小用例，不依赖四个项目的任何代码。本节结论对应 2026-11-08 的 `build\leno.exe` 快照；`src/` 正在并发修改，若源码已变需重测。

**① `switch` —— 能用（但不做穷尽检查）**

```leno
func classify(int n): string {
    switch n {
        case 1 { return "one" }
        case 2 { return "two" }
        default { return "other" }
    }
}
```

运行结果：`int switch: one,two,other`；字符串版 `str switch: A,B,?`；enum 值版 `enum switch: ok,nf,err`。
`--debug` 反汇编显示每个 case 是一条 `OP_EQ`（`OP_EQ A=3 B=1 C=2`），确认是线性比较链，但功能正确。
**判定：能用**。补充：enum 的 `switch` 不写 `default` 也能编译、无任何警告（`switch c { case Color.red ... case Color.green ... }` 输出 `red`）⇒ **穷尽性检查：没有**。

**② `enum` —— 半能用（只有 int 常量）**

```leno
enum Status { ok = 200 not_found = 404 error = 500 }
```

`_str(Status.not_found)` 输出 `404`，可用于 `switch`。但带载荷的定义：

```leno
enum JobMsg {
    Start(int id)
    Progress(int done, int total)
    Done(int id)
}
```

直接报 9 条语法错误（`期望 enum 成员名称`、`期望 ')'`、`期望 '}' 结束 enum 定义` 等）。
**判定：int 常量能用；载荷没有。** 这正是四项目把消息写成 `["progress", 已下, 总长]` 的原因之一。

**③ `map` / `filter` / `reduce` —— 能用，且类型没有丢**

```leno
var doubled = nums.map(func(int x, int i) { return x * 2 })
var evens   = nums.filter(func(int x, int i) { return x % 2 == 0 })
var total   = nums.reduce(func(int acc, int x, int i) { return acc + x }, 0)
```

输出：`map type=Array[int] value=[6, 2, 4]`、`filter type=Array[int] value=[2]`、`reduce type=int value=6`；链式 `filter().map().reduce()` 输出 `13`。
**判定：能用**。注意文档 `module_arrays.md:51-52` 写“`reduce` 的返回类型暂为 `any`”，而实测运行时 `type()` 是 `int`；文档说的是类型标注、实测取的是运行时值，**不能据此判定文档过时（待确认，静态类型未验证）**，但该描述确实容易劝退使用者。

**④ 自定义比较器 `sort` —— 没有**

```leno

```

报错：`[语义错误] 调用方法 'sort' 时参数数量不匹配: 期望 0, 实际 1`。
改模块形式 `arrays.sort(nums, fn)` 同样失败：`arrays.sort 参数数量不匹配: 期望 1, 实际 2`，并附 `参数 2 类型错误: 期望 'int'，但传入 'func(int, int):int'`。
~~**判定：没有。**~~ ✅ **已补（2026-11-09）**：`arr.sort(cmp)` 现在可用（稳定归并；回调里改数组不会崩）。

```leno

arr.sort(func(Song x, Song y) { return x.dur - y.dur })  // 按 struct 字段
```

契约与 C `qsort` / Java `Comparator` 同口径（负数⇒a 前、0⇒等、正数⇒b 前）。取消失败时的原话是
“期望 0 参”，现已支持 0 或 1 参。

> 原文说的两处手写已按此处理：[player.leno:269 `lrc_sort`](file:///d:/CLeno/LenoMusic/player.leno#L269-L300) 与 Aria `lib/lyric.leno` 的同名函数都改成了 `ord.sort(cmp)`。
