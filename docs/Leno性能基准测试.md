# Leno 性能基准测试

## 测试环境

- **操作系统**：Windows 10 x64
- **处理器**：Intel Core i5-3470（4核4线程，3.2GHz）
- **内存**：8GB DDR3
- **编译器**：MSVC（C++/Leno）、CPython 3.13.2、Lua 5.5
- **Leno 版本**：最新优化版（2026-04-30）

---

## 一、递归 Fibonacci（fib(30)）

| 语言 | 耗时 | 相对最快 |
|------|------|---------|
| C++ Release | <1ms | 1.0x |
| C++ Debug | 14ms | >14x |
| Lua 5.5 | 69ms | >69x |
| Lua 4.0 | 160ms | >160x |
| Python 3.13 | 205ms | >205x |
| **Leno（带类型注解）** | **187ms** | **>187x** |
| Leno（无类型注解） | 203ms | >203x |

> Leno 是栈式 VM，Lua 5.5 是寄存器式 VM。寄存器架构在函数调用时天然省去大量 push/pop 操作，理论上比栈式快 15-30%。Leno 通过值类型直接存储、OP_INC 快路径等优化弥补了架构劣势，差距已缩小到 2.7 倍。

### Leno 不同实现方式对比

| 实现方式 | fib(30) | fib(1000) |
|---------|---------|-----------|
| 经典递归 | 219ms | - |
| 记忆化递归 | 78ms | - |
| 迭代实现 | 0ms | 0ms |
| 尾递归 | 0ms | - |

> 迭代 fib(1000) 结果正确（209位大整数），大整数无溢出。

| `a = b + c` | 312ms | 1090ms | **3.5x** |
| `a += 1` | 172ms | 1230ms | **7.2x** |

## 六、for vs while 对比（Leno）

| 场景 | for | while | for/while |
|------|-----|-------|-----------|
| 空循环 | 93ms | 329ms | **28.3%** |
| `i++` | 187ms | 328ms | **57.0%** |
| 带循环变量 | 141ms | 390ms | **36.2%** |
| 数组添加 | 407ms | 641ms | **63.5%** |
| 嵌套循环 | 16ms | 46ms | **34.8%** |

> **for 循环全面碾压 while**，平均快 2-5 倍。`for` 使用专用 OP_FOR_PREP/OP_FOR_LOOP 字节码，`while` 每次都要重新评估条件表达式。

## 总结

### Leno vs Python

| 维度 | Leno 优势 |
|------|----------|
| 算术运算 | **4-7x** |
| 循环控制 | **2-5x**（for 循环） |
| 函数调用 | **1.2x** |
| 数组操作 | **1.3-1.5x** |
| Math 库调用 | **2.3x** |
| 递归 | **1.3x**（Leno 略慢） |

### Leno vs Lua 5.5

| 维度 | 对比 |
|------|------|
| Math 密集 | 持平（1.1x） |
| 数组插入 | Lua 快 2x |
| 递归 | Lua 快 3.2x |

### Leno VM 架构

- **架构类型**：栈式 VM（Stack-based）
- **值存储**：int/float 直接存储（不装箱），int 自动升级 BigInt（无溢出），null/string/数组/字典/函数为引用类型
- **GC**：标记-清除（Mark-and-Sweep），阈值 1MB
- **指令分发**：GCC/Clang 用 computed goto，MSVC 用 switch
- **优化**：OP_INC/OP_ADD_ASSIGN 快路径、OP_ADD int 快路径、内联 locals 数组（≤8 个局部变量免 malloc）、类型特化运算符（OP_ADD_INT、OP_SUB_INT、OP_GE_INT 等）
