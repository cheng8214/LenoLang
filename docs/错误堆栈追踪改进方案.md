# 错误堆栈追踪改进方案

## 现状分析

Leno 的异常系统**已有**基础的调用链支持：

### 已有能力

`throw_runtime_error()` 在创建异常对象时，已将调用栈信息存入 `e.stack`：

```leno
try {
    var a = 1 / 0
} catch e {
    print(e.msg)     // "除零错误"
    print(e.file)    // "script.leno"
    print(e.line)    // 2
    print(e.stack)   // ["<main>", "inner", "middle", "outer"]
}
```

异常对象是一个 Dict，包含：
| 属性 | 类型 | 说明 |
|------|------|------|
| `msg` | string | 错误消息 |
| `line` | int | 错误发生的行号 |
| `file` | string | 错误发生的文件名 |
| `stack` | array | 调用栈（函数名数组） |

### 存在的差距

| 问题 | 影响 | 位置 |
|------|------|------|
| **`e.stack` 只有函数名，缺少行号** | 无法定位每层调用的具体位置 | `vm_exception.inc` → `throw_runtime_error()` |
| **`throw "string"` 不捕获调用栈** | 用户手动 throw 的异常无 stack 信息 | `op_exception.inc` → `OP_THROW` |
| **未捕获异常不打印调用栈** | 程序崩溃时只显示一行错误，无法追踪调用链 | `vm_exception.inc` → `throw_runtime_error()` 末尾 + `op_exception.inc` → `OP_THROW` 末尾 |

---

## 改进目标

### 1. 丰富 `e.stack` 内容：每帧包含 `函数名 (文件:行号)`

**当前**：`e.stack` = `["<main>", "inner", "middle", "outer"]`

**改进后**：`e.stack` = `["<main> (script.leno:10)", "inner (script.leno:5)", "middle (script.leno:3)", "outer (script.leno:2)"]`

### 2. `throw` 语句也捕获调用栈

**当前**：`throw "error"` 抛出的是裸字符串，`catch e` 拿到的 `e` 就是字符串本身，无 `.msg`/`.stack` 等属性。

**改进后**：`throw "error"` 自动包装为异常对象，包含完整的 `.msg`/`.file`/`.line`/`.stack`。

> **兼容性**：`catch e` 中 `e` 仍然是字符串可用的（通过 `e.msg` 或直接 `print(e)` 打印消息）。检查 `e` 是否为 Dict 来决定如何访问属性。

### 3. 未捕获异常打印完整调用栈

**当前输出**：
```
[错误] script.leno:5: 除零错误
```

**改进后输出**：
```
[错误] script.leno:5: 除零错误
    at inner (script.leno:5)
    at middle (script.leno:3)
    at outer (script.leno:2)
    at <main> (script.leno:10)
```

## 实现方案

### 涉及文件

| 文件 | 改动 |
|------|------|
| `src/vm/vminc/vm_exception.inc` | 改进 `throw_runtime_error()` 的 stack 构建；新增 `build_stack_trace()` 辅助函数；未捕获异常打印调用栈 |
| `src/vm/vminc/op_exception.inc` | `OP_THROW` 中对字符串异常包装为异常对象 |

### 3.1 新增 `build_stack_trace()` 辅助函数

在 `vm_exception.inc` 中新增，用于构建包含文件名和行号的调用栈数组：

```c
// 构建调用栈数组，每帧格式: "func_name (file:line)"
static ObjArray* build_stack_trace(void) {
    ObjArray* stack_arr = arr_new(vm.frame_cnt);
    if (!stack_arr) return NULL;

    for (int i = vm.frame_cnt - 1; i >= 0; i--) {
        CallFrame* f = &vm.frames[i];

        // 获取函数名
        const char* func_name = NULL;
        if (f->closure && f->closure->function && f->closure->function->name) {
            func_name = f->closure->function->name;
        } else if (i == 0) {
            func_name = "<main>";
        } else {
            func_name = "<anonymous>";
        }

        // 获取文件名
        const char* filename = "unknown";
        if (f->chunk && f->chunk->filename) {
            filename = f->chunk->filename;
        }

        // 获取行号（当前 IP 对应的行）
        int line = 0;
        if (f->chunk && f->chunk->lines && f->ip) {
            int offset = (int)(f->ip - f->chunk->code);
            if (offset >= 0 && offset < f->chunk->len) {
                line = f->chunk->lines[offset];
            }
        }

        // 拼接 "func_name (file:line)"
        char frame_desc[BUFFER_XLARGE];
        snprintf(frame_desc, sizeof(frame_desc), "%s (%s:%d)", func_name, filename, line);
        ObjString* frame_str = str_copy(frame_desc, strlen(frame_desc));
        if (frame_str) {
            arr_write(stack_arr, stack_arr->count, val_obj((Object*)frame_str));
        }
    }
    return stack_arr;
}
```

### 3.2 改进 `throw_runtime_error()`

将现有的 stack 构建逻辑替换为调用 `build_stack_trace()`：

```c
// 替换原来的 for 循环构建 stack
ObjArray* stack_arr = build_stack_trace();
if (stack_arr) {
    ObjString* stack_key = str_copy("stack", 5);
    if (stack_key) {
        dict_set(err_dict, val_obj((Object*)stack_key), val_obj((Object*)stack_arr));
    }
}
```

### 3.3 未捕获异常打印调用栈

在 `throw_runtime_error()` 末尾，当没有找到 catch/finally 时：

```c
// 没有找到任何异常处理
// 打印完整调用栈
fprintf(stderr, "[错误] %s:%d: %s\n", filename, line, msg);
if (stack_arr && stack_arr->count > 1) {
    fprintf(stderr, "调用栈:\n");
    for (int i = 0; i < stack_arr->count; i++) {
        Value frame_val = stack_arr->elements[i];
        if (val_is_string(frame_val)) {
            fprintf(stderr, "    at %s\n", ((ObjString*)val_as_obj(frame_val))->chars);
        }
    }
}
runtime_error(msg, line);
vm.has_exception = 1;
```

### 3.4 `OP_THROW` 包装字符串异常

在 `op_exception.inc` 的 `OP_THROW` 中，当异常是字符串时，自动包装为异常对象：

```c
OPCODE(OP_THROW) {
    frame = &vm.frames[vm.frame_cnt - 1];
    Value exception = vm_stack_pop(&vm);
    if (val_is_null(exception)) {
        exception = vm.exception;
    }

    // 如果 throw 的是字符串，包装为异常对象（含 stack 信息）
    if (val_is_string(exception)) {
        ObjString* str = (ObjString*)val_as_obj(exception);
        ObjDict* err_dict = dict_new(8);
        if (err_dict) {
            // msg
            dict_set(err_dict, val_obj((Object*)str_copy("msg", 3)), exception);
            // line
            dict_set(err_dict, val_obj((Object*)str_copy("line", 4)), val_int(GET_CURRENT_LINE()));
            // file
            const char* filename = frame->chunk->filename ? frame->chunk->filename : "unknown";
            dict_set(err_dict, val_obj((Object*)str_copy("file", 4)),
                     val_obj((Object*)str_copy(filename, strlen(filename))));
            // stack
            ObjArray* stack_arr = build_stack_trace();
            if (stack_arr) {
                dict_set(err_dict, val_obj((Object*)str_copy("stack", 5)),
                         val_obj((Object*)stack_arr));
            }
            exception = val_obj((Object*)err_dict);
        }
    }

    // ... 后续逻辑不变
}
```

### 3.5 未捕获异常在 `OP_THROW` 中也打印调用栈

`OP_THROW` 末尾，当没有找到 catch/finally 时：

```c
if (vm.has_exception) {
    if (vm.current_coroutine) {
        return -1;
    }
    // 打印调用栈
    if (val_is_obj(vm.exception) && val_as_obj(vm.exception)->type == OBJ_DICT) {
        ObjDict* err = (ObjDict*)val_as_obj(vm.exception);
        // 获取 msg
        Value msg_val = dict_get(err, val_obj((Object*)str_copy("msg", 3)));
        char* msg = val_is_string(msg_val) ? strdup(((ObjString*)val_as_obj(msg_val))->chars) : strdup("未知错误");
        // 获取 file/line
        Value file_val = dict_get(err, val_obj((Object*)str_copy("file", 4)));
        Value line_val = dict_get(err, val_obj((Object*)str_copy("line", 4)));
        const char* fname = val_is_string(file_val) ? ((ObjString*)val_as_obj(file_val))->chars : "unknown";
        int ln = val_is_int(line_val) ? (int)val_as_int(line_val) : 0;

        fprintf(stderr, "[错误] %s:%d: %s\n", fname, ln, msg);
        // 打印 stack
        Value stack_val = dict_get(err, val_obj((Object*)str_copy("stack", 5)));
        if (val_is_obj(stack_val) && val_as_obj(stack_val)->type == OBJ_ARRAY) {
            ObjArray* stack_arr = (ObjArray*)val_as_obj(stack_val);
            fprintf(stderr, "调用栈:\n");
            for (int i = 0; i < stack_arr->count; i++) {
                if (val_is_string(stack_arr->elements[i])) {
                    fprintf(stderr, "    at %s\n", ((ObjString*)val_as_obj(stack_arr->elements[i]))->chars);
                }
            }
        }
        free(msg);
    } else {
        char* msg = value_to_string(exception);
        runtime_error(msg, GET_CURRENT_LINE());
        free(msg);
    }
    return -1;
}
```

## 使用示例

### 改进后的效果

```leno
func inner() {
    var arr = [1, 2, 3]
    var x = arr[10]    // 数组越界
}

func middle() {
    inner()
}

func outer() {
    middle()
}

main() {
    outer()    // 未捕获异常
}
```

**改进前输出**：
```
[错误] script.leno:3: 数组索引越界
```

**改进后输出**：
```
[错误] script.leno:3: 数组索引越界
调用栈:
    at inner (script.leno:3)
    at middle (script.leno:6)
    at outer (script.leno:10)
    at <main> (script.leno:14)
```

### `throw` 字符串也支持 stack

```leno
func validate(int x) {
    if x < 0 {
        throw "x 不能为负数"
    }
}

main() {
    try {
        validate(-1)
    } catch e {
        print(e.msg)    // "x 不能为负数"
        print(e.line)   // 3
        print(e.stack)  // ["validate (script.leno:3)", "<main> (script.leno:8)"]
    }
}
```

### 未捕获 `throw` 也打印调用栈

```leno
func check(int x) {
    if x < 0 {
        throw "invalid input"
    }
}

main() {
    check(-1)   // 未捕获
}
```

**输出**：
```
[错误] script.leno:3: invalid input
调用栈:
    at check (script.leno:3)
    at <main> (script.leno:7)
```

## 实际实现说明

### 已实现的改进

1. **`e.stack` 格式升级**：从纯函数名数组 `["inner", "middle", "<main>"]` 变为 `"func (file:line)"` 格式 `["inner (script.leno:3)", "middle (script.leno:6)", "<main> (script.leno:10)"]`。仍是字符串数组，不影响遍历。

2. **未捕获异常打印调用栈**：所有未捕获异常路径（`throw_runtime_error`、`OP_THROW`、`OP_END_TRY`）现在都会通过 `print_unhandled_exception()` 打印完整的调用栈到 stderr。

3. **`throw` 字符串向后兼容**：`throw "string"` 保持原行为，`catch e` 拿到的 `e` 仍然是字符串本身。但未捕获时也会实时构建并打印调用栈。

4. **未捕获异常消息提取**：当异常是 Dict 时，从 `e.msg` 提取消息字符串传给 `runtime_error`，避免打印整个 Dict 表示。

### 内联优化对调用栈的影响

Leno 编译器实现了函数内联优化（`codegen_inline.c`），满足以下条件的函数会被内联到调用点：
- 函数体 ≤ 8 条语句
- 不含 try-catch、switch、循环
- 无 upvalue（闭包捕获）
- 非 async、非构造/析构函数
- 无泛型类型参数
- 无默认参数
- 内联深度 ≤ 3 层

**被内联的函数不会出现在调用栈中**，因为它们没有独立的 CallFrame。这与 C/C++ 的 `-O2` 内联行为一致。

如果需要完整的调用栈信息用于调试，可以：
- 在函数中添加 `try-catch`（会使函数不被内联）
- 或使用 `--no-inline` 编译选项（如已实现）

### 涉及文件

| 文件 | 改动 |
|------|------|
| `src/vm/vminc/vm_exception.inc` | 新增 `build_stack_trace()` 和 `print_unhandled_exception()`；改进 `throw_runtime_error()` |
| `src/vm/vminc/op_exception.inc` | `OP_THROW` 和 `OP_END_TRY` 未捕获路径打印调用栈并提取消息 |

### 性能影响

- `build_stack_trace()` 只在异常发生时调用，不在热路径上
- `print_unhandled_exception()` 只在未捕获异常时调用
- 正常执行流程零开销
