# Leno 包管理与安装使用指南

## 快速入门

### 三步上手

```bash
# 1. 创建一个包
leno --init my-pkg

# 2. 编写并安装到全局缓存
leno --install my-pkg

# 3. 在任意项目中使用
# import "my-pkg"   # 不需要 .leno 后缀！
```

**完整示例：**

```leno
// my-pkg/lib/my-pkg.leno - 包的模块代码
export func hello() {
    print("Hello from my-pkg!")
}

export func add(var a, var b) {
    return a + b
}

export var VERSION = "0.1.0"

// 私有函数（不导出）
func _internal_helper() {
    return "internal"
}
```

```leno
// 任意项目的 main.leno - 使用包
import "my-pkg"

main() {
    my-pkg.hello()          // Hello from my-pkg!
    var result = my-pkg.add(1, 2)
    print(result)           // 3
    print(my-pkg.VERSION)   // 0.1.0
}
```

## 1. 包的概念

### 1.1 什么是 Leno 包？

一个 Leno 包是一个带 `leno.toml` 配置文件的目录，包含可复用的 Leno 模块代码。包可以被安装到全局缓存，然后在任意项目中使用 `import "包名"` 直接导入。

### 1.2 包 vs 文件模块

| 特性 | 文件模块 | 包 |
|------|---------|-----|
| 导入方式 | `import "path/to/module.leno"` | `import "包名"` |
| 版本管理 | 无 | `leno.toml` 中声明版本 |
| 依赖管理 | 手动处理 | `leno.toml` 声明依赖 |
| 导出控制 | `export` 关键字 | `export` 关键字 |
| 安装方式 | 复制文件 | `leno --install` |
| 存储位置 | 项目内 | 全局缓存 `~/.leno/pkgs/` |

## 2. 创建包

### 2.1 使用 `leno --init`

```bash
# 在当前目录创建包（目录名为包名）
leno --init

# 创建指定名称的包
leno --init my-package

# 创建到指定目录
leno --init path/to/my-package
```

### 2.2 自动生成的项目结构

运行 `leno --init my-package` 后会生成：

```
my-package/
├── leno.toml              # 包配置文件
├── lib/                   # 模块代码目录
│   └── my-package.leno    # 默认示例模块
├── src/                   # 入口/测试代码
│   └── main.leno          # 示例入口文件
├── native/                # 原生库目录
├── examples/              # 示例代码
├── test/                  # 测试代码
└── .gitignore             # 版本控制忽略文件
```

### 2.3 自动生成的示例代码

**leno.toml：**

```toml
[package]
name = "my-package"
version = "0.1.0"
description = "A Leno package"
authors = ""
license = "MIT"
leno_version = ">=1.0.0"

[dependencies]

[dev-dependencies]

[modules]
root = "lib"
```

**lib/my-package.leno：**

```leno
// my-package - 示例模块

export func hello() {
    print("Hello from my-package!")
}
```

## 3. leno.toml 配置详解

### 3.1 `[package]` - 包基本信息

```toml
[package]
name = "my-lib"                  # 包名（必填，也是 import 时使用的名称）
version = "1.2.0"                # 语义化版本号
description = "我的包描述"        # 包描述
authors = "Your Name"            # 作者
license = "MIT"                  # 开源许可证
leno_version = ">=1.0.0"         # 要求的 Leno 编译器最低版本
```

### 3.2 `[dependencies]` - 依赖管理

```toml
[dependencies]
http_client = "~1.2.0"           # 兼容版本：>=1.2.0 <1.3.0
json_parser = ">=2.0.0"          # 最低版本
logger_lib  = "1.0.0"            # 精确版本
any_lib     = "*"                # 任意版本
some_lib    = ">=1.0.0, <2.0.0"  # 版本范围
```

**版本约束语法：**

| 写法 | 含意 | 约束类型 |
|------|------|----------|
| `"1.0.0"` | 精确匹配 1.0.0 | `VER_EXACT` |
| `"~1.2.3"` | 兼容版本: `>=1.2.3` 且 `<1.3.0` | `VER_COMPAT` |
| `">=1.0.0"` | 最小版本要求 | `VER_GTE` |
| `">=1.0.0, <2.0.0"` | 版本范围 | `VER_RANGE` |
| `"*"` | 任意版本 | `VER_ANY` |

### 3.3 `[dev-dependencies]` - 开发依赖

只在开发/测试时使用的依赖，语法同 `[dependencies]`：

```toml
[dev-dependencies]
test_framework = "~0.1.0"
benchmark_lib  = "*"
```

### 3.4 `[dependency-sources]` - 依赖源配置

为 `[dependencies]` 中的每个包指定 Git 仓库地址。安装依赖时，编译器会自动 `git clone` 并安装。

**支持 Monorepo**：多个包放在同一个仓库里，用子目录路径指定。

```toml
[dependencies]
http_client = "~1.2.0"
json_parser = ">=2.0.0"
pkg_hello    = "~0.1.0"
pkg_math     = "~0.1.0"

[dependency-sources]
http_client = "gitee:leno/http-client"              # 独立仓库
json_parser = "https://gitee.com/leno/json-parser.git"  # 完整 URL
pkg_hello   = "gitee:leno/monorepo/pkg-hello"       # monorepo 子包
pkg_math    = "gitee:leno/monorepo/pkg-math"        # 同一仓库下的另一个子包
```

> **支持的源格式：**
> - 平台简写：`gitee:user/repo`、`github:user/repo`、`gitlab:user/repo`
> - **Monorepo 子包**：`gitee:user/repo/pkg-a`（仓库中的子目录）
> - 完整 URL：`https://gitee.com/user/repo.git`
> - SSH 格式：`git@github.com:user/repo.git`

使用示例：

```bash
# 在项目根目录运行，自动安装所有依赖（有 source 的会从 git clone）
leno --install
```

输出：

```
[leno install] 从 'my-project' 安装 4 个依赖...
  [安装] http_client ← gitee:leno/http-client
[leno install] 包 'http-client' (1.2.0) 安装成功!
  [安装] json_parser ← https://gitee.com/leno/json-parser.git
[leno install] 包 'json-parser' (2.0.0) 安装成功!
  [安装] pkg_hello ← gitee:leno/monorepo/pkg-hello
[leno install] 从 Git 安装: https://gitee.com/leno/monorepo.git (子目录: pkg-hello)
[leno install] 包 'pkg-hello' (0.1.0) 安装成功!
  [安装] pkg_math ← gitee:leno/monorepo/pkg-math
[leno install] 包 'pkg-math' (0.1.0) 安装成功!
[leno install] 完成: 4 成功, 0 跳过, 0 失败
```

### 3.5 `[modules]` - 模块配置

```toml
[modules]
root = "lib"        # 模块文件根目录，默认为 "lib"
```

### 3.6 `[native-libs.*]` - 原生库映射

```toml
[native-libs.sqlite3]
win   = "native/sqlite3.dll"
linux = "native/libsqlite3.so"
mac   = "native/libsqlite3.dylib"

[native-libs.crypto]
win   = "native/crypto.dll"
linux = "native/libcrypto.so"
```

### 3.7 完整配置示例

```toml
[package]
name = "awesome-lib"
version = "1.0.0"
description = "一个超棒的 Leno 库"
authors = "Leno Team"
license = "MIT"
leno_version = ">=1.0.0"

[dependencies]
http_client = "~1.2.0"
json_parser = ">=2.0.0"

[dependency-sources]
http_client = "gitee:leno/monorepo/http-client"      # monorepo 子包
json_parser = "gitee:leno/monorepo/json-parser"       # 同一仓库的子包

[dev-dependencies]
test_runner = "~0.1.0"

[modules]
root = "lib"

[native-libs.sqlite3]
win   = "native/sqlite3.dll"
linux = "native/libsqlite3.so"
mac   = "native/libsqlite3.dylib"
```

## 4. 包的模块编写

### 4.1 `export` 导出控制

使用 `export` 关键字显式声明导出：

```leno
// lib/my-lib.leno

// ✅ 导出函数
export func greet(string name) {
    print("Hello, " + name + "!")
}

// ✅ 导出变量
export var PI = 3.14159
export var VERSION = "1.0.0"

// ✅ 导出结构体
export struct Point {
    int x = 0
    int y = 0
}

// ✅ 导出枚举
export enum Status {
    OK,
    ERROR,
    PENDING
}

// ❌ 没有 export = 模块私有，外部不可见
func _internal_helper() {
    return "secret"
}

var _cache = {}    // 私有缓存
```

### 4.2 包模块命名约定

包的模块文件 `lib/<包名>.leno` 是包的入口模块：

```
my-package/
├── leno.toml
└── lib/
    ├── my-package.leno       # 包入口（自动被 import "my-package" 找到）
    ├── utils.leno            # 子模块（通过 import "my-package/utils" 访问）
    └── internal/
        └── helper.leno       # 子模块
```

## 5. 安装与缓存

### 5.1 全局缓存目录

```
# Windows
C:\Users\<用户名>\.leno\pkgs\

# Linux / macOS
~/.leno/pkgs/
```

缓存结构：

```
~/.leno/pkgs/
├── package-a/
│   ├── leno.toml
│   └── lib/
│       └── package-a.leno
├── package-b/
│   ├── leno.toml
│   └── lib/
│       └── package-b.leno
└── ...
```

### 5.2 安装一个包

#### 从本地目录安装

```bash
# 从本地目录安装
leno --install path/to/my-package

# 安装当前目录的包
leno --install .
```

示例输出：

```
[leno install] 包 'my-package' (0.1.0) 安装成功!
  安装到: C:\Users\Admin\.leno\pkgs\my-package\
```

#### 从 Git 远程安装

支持从 Git 仓库直接安装包（前置要求：系统已安装 Git）。

**独立仓库：**

```bash
# 平台简写格式
leno --install gitee:user/my-package      # Gitee
leno --install github:user/my-package     # GitHub
leno --install gitlab:user/my-package     # GitLab
leno --install git:user/my-package        # 等同 github:

# 完整 HTTPS URL
leno --install https://gitee.com/user/my-package.git

# SSH 格式
leno --install git@gitee.com:user/my-package.git
```

**Monorepo（一个仓库放多个包）：**

```bash
# 安装仓库中某个子目录的包
leno --install gitee:user/monorepo/pkg-hello
#                    └──────────┘  └──────┘
#                    仓库路径      子目录（包名）
```

**安装流程：** 解析 URL → `git clone --depth 1` 整个仓库 → 定位子目录 → 读取 `leno.toml` → 复制到全局缓存 → 清理临时目录。

示例输出（monorepo 子包）：

```
[leno install] 从 Git 安装: https://gitee.com/user/monorepo.git (子目录: pkg-hello)
[leno install] git clone --depth 1...
[leno install] 包 'pkg-hello' (0.1.0) 安装成功!
  安装到: C:\Users\Admin\.leno\pkgs\pkg-hello\
```

### 5.3 安装所有依赖

在项目根目录（包含 `leno.toml` 的目录）下运行：

```bash
# 读取 leno.toml 的 [dependencies] 并安装
leno --install
```

对于在 `[dependency-sources]` 中指定了 Git 源的依赖，会自动执行 `git clone --depth 1` 从远程仓库拉取并安装。没有指定源的依赖会提示手动操作。

示例输出：

```
[leno install] 从 'my-project' 安装 3 个依赖...
  [跳过] http_client (已安装)
  [安装] json_parser ← gitee:leno/json-parser
[leno install] 包 'json-parser' (2.0.0) 安装成功!
  [失败] some_lib - 没有指定 git 源
         提示: 在 leno.toml 中添加 [dependency-sources]
         some_lib = "gitee:user/some_lib"
         或用 'leno --install <git-url>' 手动安装
[leno install] 完成: 1 成功, 1 跳过, 1 失败
```

### 5.4 覆盖已安装的包

重复安装同名包会自动覆盖旧版本：

```bash
leno --install my-package     # 第一次安装
leno --install my-package     # 覆盖安装，更新到最新代码
```

## 6. 使用包（导入）

### 6.1 基本导入

```leno
// 直接导入包（无需 .leno 后缀）
import "my-package"

main() {
    my-package.hello()
}
```

### 6.2 带别名导入

```leno
import "my-package" as mp

main() {
    mp.hello()
    print(mp.VERSION)
}
```

### 6.3 搜索路径优先级

当执行 `import "my-package"` 时，编译器按以下顺序查找 `my-package.leno`：

1. **项目 `lib/` 目录** - `<项目根>/lib/my-package.leno`
2. **依赖缓存** - `leno.toml` 中声明的依赖对应的缓存目录
3. **源文件所在目录** - 当前 `.leno` 文件所在目录
4. **全局缓存** - `~/.leno/pkgs/*/lib/my-package.leno`

```bash
# 搜索过程示意
项目/lib/                          → 项目内 lib 目录
~/.leno/pkgs/some_dep/lib/        → 依赖的 lib 目录
源码所在目录/                       → 当前 .leno 文件所在目录
~/.leno/pkgs/my-package/lib/      → 全局缓存
```

### 6.4 文件模块 vs 包导入对比

```leno
// 文件模块 - 需要完整路径 + .leno 后缀
import "../lib/my_utils.leno" as utils

// 包导入 - 只需包名，自动在搜索路径中查找
import "my_utils"

// 包导入也可以指定别名
import "my_utils" as u
```

## 7. 完整工作流示例

### 7.1 场景：创建一个数学库并在另一个项目中使用

**步骤 1：创建数学库包**

```bash
leno --init leno-math
cd leno-math
```

**步骤 2：编写模块代码**

编辑 `lib/leno-math.leno`：

```leno
// leno-math 数学工具库

export var PI = 3.1415926535
export var E  = 2.7182818284

export func add(var a, var b) {
    return a + b
}

export func multiply(var a, var b) {
    return a * b
}

export func factorial(int n):int {
    if n <= 1 {
        return 1
    }
    return n * factorial(n - 1)
}

export func square(var x) {
    return x * x
}

// 私有辅助函数（不导出）
func _validate(Number x) {
    // 内部验证逻辑
}
```

**步骤 3：安装到全局缓存**

```bash
leno --install .
```

输出：

```
[leno install] 包 'leno-math' (0.1.0) 安装成功!
  安装到: C:\Users\Admin\.leno\pkgs\leno-math\
```

**步骤 4：在另一个项目中使用**

```bash
mkdir ../my-project
cd ../my-project
```

创建 `main.leno`：

```leno
import "leno-math"

main() {
    print("===== leno-math 库测试 =====")

    print("圆周率: " + leno-math.PI)
    print("自然常数: " + leno-math.E)

    var sum = leno-math.add(10, 20)
    print("10 + 20 = " + sum)

    var product = leno-math.multiply(6, 7)
    print("6 * 7 = " + product)

    var sq = leno-math.square(8)
    print("8 的平方 = " + sq)

    var fact = leno-math.factorial(5)
    print("5! = " + fact)
}
```

**运行：**

```bash
leno main.leno
```

### 7.2 场景：带依赖的包

**步骤 1：创建 A 包（基础库）**

```bash
leno --init lib-base
# 编写 lib/lib-base.leno...
leno --install .
```

**步骤 2：创建 B 包（依赖 A）**

```bash
leno --init lib-advanced
```

编辑 `leno.toml`，添加依赖：

```toml
[package]
name = "lib-advanced"
version = "0.1.0"
description = "依赖 lib-base 的高级库"
license = "MIT"

[dependencies]
lib-base = ">=0.1.0"
```

编写 `lib/lib-advanced.leno`：

```leno
import "lib-base"

export func advanced_func(var x) {
    var basic = lib-base.some_func(x)
    return basic * 2
}
```

**步骤 3：安装依赖**

编辑 `leno.toml`，添加 Git 源：

```toml
[dependencies]
lib-base = ">=0.1.0"

[dependency-sources]
lib-base = "gitee:user/lib-base"
```

然后一键安装：

```bash
# 自动从 git clone lib-base 并安装
leno --install
```

**步骤 4：使用 B 包**

```leno
import "lib-advanced"

main() {
    var result = lib-advanced.advanced_func(42)
    print(result)
}
```

> **注意**：运行时，编译器会自动读取 `leno.toml` 中的依赖声明，将依赖包的 `lib/` 目录加入搜索路径，因此 `import "lib-advanced"` 也能找到 `lib-advanced` 所依赖的 `lib-base`。**依赖库需先安装到全局缓存中（通过 `[dependency-sources]` 声明 Git 源后 `leno --install` 一键安装）。**

## 8. 命令参考

| 命令 | 说明 |
|------|------|
| `leno --init` | 在当前目录创建包项目 |

## 9. 最佳实践

### ✅ 推荐做法

1. **始终使用 `export` 显式导出**
   ```leno
   export func public_api() { }
   func _internal_helper() { }    // 不导出
   ```

2. **包名使用小写 + 连字符**
   ```
   my-awesome-lib    ✅
   MyAwesomeLib      ❌ (不符合约定)
   my_awesome_lib    ❌ (风格不统一)
   ```

3. **一个包一个核心功能**
   ```bash
   leno --init http-client    # HTTP 客户端
   leno --init json-parser    # JSON 解析器
   leno --init logger-lib     # 日志库
   ```

4. **遵循语义化版本**
   ```
   0.1.0  → 初始开发
   1.0.0  → 首个稳定版
   1.1.0  → 新增功能（向后兼容）
   1.1.1  → Bug 修复
   2.0.0  → 重大变更（不兼容）
   ```

5. **在 `lib/` 中组织模块**
   ```
   my-lib/
   └── lib/
       ├── my-lib.leno       # 包入口
       ├── utils.leno        # 工具函数
       ├── types.leno        # 类型定义
       └── internal/
           └── core.leno     # 内部实现
   ```

### ❌ 避免的做法

1. **在模块初始化时执行副作用**
   ```leno
   // ❌ 不好 - 导入时就有副作用
   print("模块已加载")
   var conn = open_database()  // 导入时就连接数据库
   ```

2. **导出过多内部细节**
   ```leno
   // ❌ 不好
   export var _internal_counter  // 暴露内部状态
   export func _parse_internal() // 暴露内部实现
   ```

3. **忘记安装依赖包**
   ```bash
   # ❌ 直接运行带依赖的项目但还没安装依赖
   leno main.leno               # 可能找不到依赖
   
   # ✅ 先安装依赖
   leno --install dependency-pkg
   leno main.leno
   ```

## 10. 常见问题

### Q: 安装的包存在哪里？

A: 全局缓存目录：
- Windows: `C:\Users\<用户名>\.leno\pkgs\`
- Linux/macOS: `~/.leno/pkgs/`

### Q: 如何更新已安装的包？

A: 重新安装即可覆盖：
```bash
leno --install path/to/package
```

### Q: 包名和目录名必须一致吗？

A: 包名由 `leno.toml` 中的 `[package].name` 决定，但推荐与目录名保持一致。

### Q: 同一个包的不同版本怎么共存？

A: 目前全局缓存中每个包只保留最新版本。如需多版本共存，可以将不同版本放在不同目录，通过不同包名区分。

### Q: 如何发布/共享我的包？

A: **推荐 Monorepo**：把所有包放在同一个 Git 仓库里，每个子目录一个包。

```bash
# 创建 monorepo 仓库
mkdir my-leno-libs && cd my-leno-libs
git init

# 添加要发布的包（子目录）
leno --init pkg-json
leno --init pkg-http

# 推送到 Gitee
git add -A && git commit -m "publish"
git remote add origin https://gitee.com/user/my-leno-libs.git
git push -u origin master

# 使用者：一行安装任意子包
leno --install gitee:user/my-leno-libs/pkg-json
```

> 也可以每个包一个独立仓库：`leno --install gitee:user/pkg-name`

### Q: `import "xxx"` 找不到包怎么办？

A: 检查以下几点：
1. 包是否已经用 `leno --install` 安装到全局缓存？
2. 包名是否拼写正确（与 `leno.toml` 中的 `name` 一致）？
3. 包的 `lib/` 目录下是否有对应的 `.leno` 文件？

***

> **核心原则**：`leno --init` 创建包 → `leno --install` 安装到全局缓存 → `import "包名"` 随处使用。三步即可实现代码复用。
