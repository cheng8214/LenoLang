## L1【P1】`as Array[Array[string]]` 遇到混合类型，整块静默返回 null

### 现象

Aria 的 `library.json` 里有一条「最近播放」记录的第 6 项是**数字** `0`（本该是空串或
`"ff"`）：

```json
{"recent": [["2668005064","童话镇","梁玖希","4:17","…ff_2668005064.jpg",0]]}
```

`library.load` 是这么读的：

```leno
var rows = rv as Array[Array[string]]
if rows != null {
    for rows to r { … }        // ← 整个列表都不进来了
}
```

**一行脏数据 ⇒ 整块 recent 被丢弃**，而且**一句日志都没有**。用户看到的是「继续收听」
空空如也，只会以为数据丢了或自己清空了。

### 最小复现（已实测）

```leno
import jsons as jsons

main() {
    var d = jsons.decode("{\"recent\":[[\"id\",\"歌名\",\"艺人\",\"4:17\",\"cover.jpg\",0]]}")
    if d is Dict[string, any] => m {
        var rows = m["recent"] as Array[Array[string]]
        if rows == null { print("null：整块丢弃\n") }
        else { print("成功，第6项='" + rows[0][5] + "'\n") }
    }
}
```

实测输出：

```
null：整块丢弃
```

对照：同一份数据**编码**这边是正常的（int 原样输出 `0`），问题只在**反序列化的类型断言**。

### 根因落点

`as` 的数组转换是"整组严格匹配"：只要有一个元素类型不符，整个 `Array` 转换失败返回
`null`，而调用方通常写成 `if rows != null { … }`（合理防御）⇒ 失败路径就是**静默丢数据**。

### 建议修法

1. **逐元素宽松转换**：目标是 `Array[Array[string]]` 时，元素能转就转（`0` → `"0"`、
   `true` → `"true"`），转不了再整块失败；
2. 或者提供显式宽松函数（`jsons.str_rows(v)`) 供持久化读取使用，`as` 保持严格；
3. 无论哪种，**失败时至少 `print` 一行**（带键名与原因）。当前 `null` 完全无声。

### 应用侧规避（已用于 Aria）

写入端保证元素类型统一：`if s.src == "ff" then "ff" else "kuwo"`（不写空串，也不写数字）。
读取端只认 `"ff"`，其它（`""` / `"kuwo"` / 历史遗留的 `"0"`）一律归空。

### 附：一条**存疑**记录（未能复现，供参考）

同一条记录最初出现时，第 6 项是**不带引号的** `0`。我试过三种路径都没能复现出这个
编码结果：

```leno
Array[Array[string]] rows = [["id","歌名","艺人","4:17","cover.jpg",""]]
print(jsons.encode(rows))                 // ⇒ [...,""]   ✓ 正常

Dict[string, any] d = {}
d["recent"] = rows
print(jsons.encode(d))                    // ⇒ {"recent":[[...,""]]}   ✓ 正常

var back = jsons.decode(jsons.encode(d))  // 往返第 6 项 = '' 长度 0   ✓ 正常
```

⇒ **"空串被编码成 0"这个猜测不成立**，真实来源未查明（可能是某次历史版本的写入，
或其它我未覆盖的装箱路径）。这条只作线索留档，别照着它去改 `jsons.c` 的 string 分支。

## L2【P1】单槽回调重复注册会静默覆盖

### 现象

设置窗的「蒙版透明度」滑块，注册了**两处** `on_change`：

```leno
veilS.on_change(func(float v) { … onVeil(v) … })    // ① 带实时预览
veilS.on_change(func(float v) { … note.set_text(…) }) // ② 旧的那份，写在后头
```

后注册的整段顶掉前一个 ⇒ 拖动时主窗口**完全没反应**，只有点「保存」才生效。
用户侧表现是"我拖动看不到窗口变化"，排查成本很高（两处代码隔了 40 行，肉眼看不出冲突）。

### 根因落点

```leno
// build/leno_module/LenoSDL3/lib/sdl_slider.leno:113
func on_change(func(float):void cb) { onChange = cb }
```

同类单槽（都在 `lib/` 里，`xxx = cb` 的写法）：

| 控件 | 方法 | 文件 |
|---|---|---|
| Slider | `on_change` | `sdl_slider.leno:113` |
| Window | `setOverlay` | `sdl_window.leno`（全局唯一渲染回调槽） |
| Table | `set_cell_builder` | `sdl_table.leno:1032` |
| 多个控件 | `on_click` / `on_select` / `on_dbl_click` … | 各自文件 |

### 建议修法（二选一，按代价排）

1. **最小改动**：重复注册时 `print("[warn] Slider.on_change 被重复注册，前一个回调已丢弃")`。
   保留"后覆盖前"的语义，但让人看得见。成本几乎为 0。
2. **更彻底**：改成 `add_change(cb)` 累加语义（数组存回调），`on_change` 保留为"清空后设一个"。
   注意这会改变现有调用方的语义，需要审计。

`setOverlay` 建议单独看：它是**全局唯一槽位**，Aria 的 `ARIA_SHOT` 截图钩子和 toast 曾经
互相顶掉（截图模式下 toast 不显示）。本轮通过"toast 上升为框架浮层"绕开了，但槽位本身
仍是 1 ⇒ 建议文档里明确写"一个窗口只能有一个 overlay 回调"，或改成数组。

## L3【P1】`threads.start` 不校验参数个数（默认参数也不补齐）

### 现象

```leno
// 工作线程入口：后加了一个可空控制通道，给了默认值
export func fetch_url(string url, string path, Channel ch, Channel? ctl = null) { … }

// 调用点（改签名时漏改的那一处）
threads.start(workers.fetch_url, sg.url, f, urlCh)        // ← 3 个参数
```

编译 `--check` **通过**，运行到这条路径直接抛：

```
[错误] threads.start(): 入口函数期望 4 个参数，实际传了 3 个
（线程入口由 VM 直接调用，默认参数不会被补齐）
```

错误信息本身写得非常好（直接给了根因），问题是**发现得太晚**——只有真实播放/下载到那条
分支才炸，而它藏在 5000 行代码的一个播放回调里。

### 根因落点

`src/module/threads/threads.c`：`threads.start` 在运行期才按函数签名比对实参个数。

### 建议修法

`threads.start` 的第一个参数在**编译期**就能解析到具体函数（`workers.fetch_url` 是模块
符号）⇒ 参数个数不符在编译期报错，成本远低于运行期。

如果编译期做不到（比如目标可能是函数变量），退一步：

- 保留运行期检查，但在 `--check` 模式下也**静态扫描** `threads.start(函数名, ...)` 这种
  字面量形式，报"参数个数不符"；
- 或者在文档/`threads使用指南.md` 里显著标注：**线程入口禁止使用默认参数**。

## L4【P2】`string.len()` 是字节数，`slice()` 是字符下标

### 现象

```leno
string s = "周杰伦 - 晴天"
int n = s.len()          // 字节数（中文 3 字节/字）
string t = s.slice(0, 2) // 字符下标（前 3 个字符）
```

两种口径混在一起，于是代码里出现大量这类注释和绕行：

```leno
// ⚠ 不能用 `byte_slice` 切文件名：中文是多字节，按字节切会把字切断（实测显示成 `刘若@@` ✗）
//   ⇒ 一律走 `split`（按码点/子串处理，不涉及偏移 ✓）
string t = base
var dot = strings.split(base, ".")
if dot.len() >= 2 { … }
```

Aria 的 `downloads.scan`、`library` 的路径处理、Toast 的超宽裁剪，全都得先想一遍
"这里该用字节还是字符"。

### 建议

二选一把口径统一（会 breaking，建议一次做完）：

1. `len()` 返回**字符数**，新增 `byte_len()`；`slice` 保持字符下标 ⇒ 完全按"文本"语义；
2. 或者 `slice` 保持字节，另加 `slice_chars()` ⇒ 按"字节"语义，文本处理显式选字符版。

现状的麻烦不是"哪种对"，而是**同一个类型上两套下标并行**，每处调用都要停下来推理。

## L5【P2】控件 `set()` 的未知选项只 print

### 现象

```leno
HBox box = SDL3.createHBox({w: 30, h: 14, tip: "来自小易"})   // HBox 没有 tip
```

运行日志：

```
[ui] HBox.set()：不认识的选项 'tip' —— 你是不是想要 'clip'？
```

程序继续跑，该属性静默丢弃。

**这个"did you mean"做得很好**，比大多数框架强。但因为它不阻断，问题只能在日志里发现
（我的截图验证跑了两轮才注意到这行）。

### 建议

- 保持 GUI 场景不崩（合理）；
- 但可以在 `--check` / 严格模式下把"未知选项"升级为编译期错误或非零退出码；
- 至少让这类日志带上文件:行号（现在只有选项名，一眼看不出是哪个 `createHBox`）。

## 已修复（本轮，供对照提交）

### F1 `Table.set_cell` 改数据不请求重绘

```leno
// 修之前：只改数组，画面不动 ⇒ 调用方漏了 markFrameRedraw 就"进度条卡住"
func set_cell(int r, int c, string v) { _rows[r][c] = v; invalidate_fitted() }
```

修法：值真变了就 `core.markFrameRedraw()`，值没变直接返回（省一次重绘请求）。
副作用收益：下载进度可以只 `set_cell` 三格，不必整页重建 ⇒ **hover / 滚动位置不再丢失**。

### F2 `Table.recompute_cols` 与 `compute_sb` 扣减口径不一致

`recompute_cols` 用 `avail = w - iconW - gx()`，`compute_sb` 用 `bodyW0 = w - 8 - fw - gx()`
——差一个右边距 8px。后果：应用把 `col_ratios` 写成合计 **1.00**（最自然的写法）就必然
溢出 8px ⇒ 底部常驻横向滚动条，**放大窗口也不消失**（差值固定）。

修法：`avail` 改成与 `bodyW0` 同口径（减 8 / 冻结列 / 行号槽）。

### F3 通用 Toast（`sdl_toast.leno`）

- 与 `tooltip` 同构的全局浮层，不占布局、不吃事件、绝对时刻算淡入淡出；
- 停留期挂起，只在动画区间唤醒（替代应用侧 33ms 定时器空转）；
- 顺带解决 `setOverlay` 单槽被截图钩子顶掉的问题。

## 给应用的「防身规则」（不是语言 bug，但会被反复踩）

1. **线程入口函数不要用默认参数**，所有实参显式给全（见 L3）。
2. **单槽回调先判空再注册**，且全项目搜一遍同一个控件有没有第二处注册（见 L2）。
3. **持久化的数组元素类型要统一**（全 string 或全 int），脏一个元素就会让
   `as Array[Array[string]]` 整块返回 null、数据静默消失（见 L1）。
4. **回调里读 struct 字段前先确认捕获语义**：闭包拿到的是创建时的副本，可变状态放
   `Array[T]` 单元素数组（Aria 的 `toastTxt[0]` / `dlLyric[0]` 就是这个原因）。
5. **表格宽度别自己猜**：布局会按容器宽 `set_size` 重算，`col_ratios` 合计留 2% 余量最稳。
