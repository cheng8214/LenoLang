## 架构前提

Leno VM 是"带局部变量槽位的混合栈式虚拟机"：
- 操作数栈：`vm.stack[]` + `vm.sp`
- 局部变量：`frame->locals[]`（随机访问，不经过栈）
- 已有的融合指令先例：`OP_SET_LOCAL_POP`、`OP_INC_LOCAL_NOPUSH`、`OP_MOVE_LOCAL_POP`、
  `OP_CALL_GLOBAL_FUNC`、`OP_INVOKE_METHOD`、`OP_CALL_NATIVE`
- 分发方式：GCC labels-as-values 跳转表（`VM_USE_JUMPTABLE`）

这些融合指令的设计哲学是：**允许指令直接读写 local slot，不经过操作数栈**。
以下方案完全延续此设计。

## ✅ 已完成：方案 5 — `OP_SET_LOCAL_CONST`（常量赋值合并）

**状态**：已实现、已测试、已合入

**问题**：字节码中大量 `OP_CONST + OP_SET_LOCAL_POP` 配对

```
OP_CONST 2 (0)          ; 压常量到栈（3 字节）
OP_SET_LOCAL_POP 1       ; 弹出存入 local（3 字节）
```
= 6 字节，1 次 push + 1 次 pop + 2 次 fetch/decode

**统计**：`benchHit` 函数前 30 条指令中 9 对，`benchHitSingle` 中 8 对，`trace` 中 7 对。

**方案**：新增 `OP_SET_LOCAL_CONST const_idx(2) local_slot(2)`（5 字节），直接从常量表读值写入 local slot，完全不碰栈。

**VM 实现**（`op_variables.inc`）：
```c
OPCODE(OP_SET_LOCAL_CONST) {
    frame = &vm.frames[vm.frame_cnt - 1];
    uint16_t const_idx = READ_SHORT();
    uint16_t slot = READ_SHORT();
    Value value = frame->chunk->constants[const_idx];
    if (frame->locals != NULL) {
        if (likely(slot < frame->local_count)) {
            frame->locals[slot] = value;
        } else {
            runtime_error("局部变量索引越界", GET_CURRENT_LINE());
            return -1;
        }
    } else {
        vm.stack[frame->stack_base + slot] = value;
    }
    DISPATCH;
}
```

**Codegen 触发**（`codegen_stmt.c` → `gen_var_decl`）：
当 `var x = <常量>` 满足以下条件时直接发射 `OP_SET_LOCAL_CONST`：
- init 是 `AST_NUM` / `AST_STRING` / `AST_BOOL` / `AST_NULL`
- 目标是 `SYM_LOCAL`
- 无类型转换（`!has_cast`，跳过 `TYPE_INFER`）
- 无特殊处理（非 `TYPE_PTR_GENERIC` / `TYPE_FACE`）
- 非多返回值

**优化后字节码**：
```
0010   88 OP_SET_LOCAL_CONST   const=2 slot=1     ; var sum = 0.0
0015   89 OP_SET_LOCAL_CONST   const=3 slot=2     ; var si = 0
```

**收益**：每处省 1 字节 + 1 次 push + 1 次 pop + 1 次 fetch/decode。

**修改文件**：
- `src/include/leno_vm.h` — 添加 `OP_SET_LOCAL_CONST` 枚举
- `src/vm/vminc/vm_run.inc` — 添加跳转表条目
- `src/vm/vminc/op_variables.inc` — 添加 VM 实现
- `src/codegen/codegen_emit.c` — 添加 `emit_set_local_const` 函数
- `src/codegen/codegen.h` — 声明
- `src/codegen/codegen_stmt.c` — `gen_var_decl` peephole 优化
- `src/debug.c` — opcode 名称表 + disassemble

## ✅ 已完成：方案 1 — `OP_ACC_FIELDS`（对象多字段累加）

**状态**：已实现、已测试、已合入

**问题**：`benchIndex` 核心循环中 `sum += s.cx + s.cy + s.cz + s.r`，同一对象被重复压栈 4 次

**优化前字节码**（13 条指令）：
```
0052  92 OP_GET_LOCAL  1          ; sum
0054  92 OP_GET_LOCAL  8          ; s（第 1 次）
0057  92 OP_GET_FIELD  0          ; s.cx
0059  92 OP_GET_LOCAL  8          ; s（第 2 次，重复！）
0062  92 OP_GET_FIELD  1          ; s.cy
0064  92 OP_ADD_FLOAT
0065  92 OP_GET_LOCAL  8          ; s（第 3 次，重复！）
0068  92 OP_GET_FIELD  2          ; s.cz
0070  92 OP_ADD_FLOAT
0071  92 OP_GET_LOCAL  8          ; s（第 4 次，重复！）
0074  92 OP_GET_FIELD  3          ; s.r
0076  92 OP_ADD_FLOAT
0077  92 OP_ADD
0078  92 OP_SET_LOCAL  1
0081  92 OP_POP
```

**方案**：新增 `OP_ACC_FIELDS count(1) field_idx_0(1) ... field_idx_N-1(1)`
- 弹出对象 1 次
- 内部循环读取 N 个字段累加（`val_as_num_ex`）
- 压入最终 `val_float(sum)` 结果

**VM 实现**（`op_struct.inc`）：
```c
OPCODE(OP_ACC_FIELDS) {
    frame = &vm.frames[vm.frame_cnt - 1];
    uint8_t count = READ_BYTE();
    Value obj_val = vm_stack_pop(&vm);
    ObjStruct* obj = (ObjStruct*)val_as_obj(obj_val);
    ObjStructDef* def = obj->def;
    double sum = 0.0;
    for (int i = 0; i < count; i++) {
        uint8_t field_idx = READ_BYTE();
        Value fv = struct_get_field(obj, field_idx);
        sum += val_as_num_ex(fv);
    }
    vm_stack_push(&vm, val_float(sum));
    DISPATCH;
}
```

**Codegen 触发**（`codegen_expr.c` → `gen_binary`）：
在 `TOK_PLUS` 分支前调用 `try_emit_acc_fields`：
1. `collect_acc_fields` 递归收集 AST_BINOP(+) 链中所有 `AST_FIELD_ACCESS` 叶子
2. 验证所有叶子引用同一对象（同一 local slot）
3. 验证表达式 `cached_type` 为 `TYPE_FLOAT`
4. 满足条件则发射 `GET_LOCAL obj + OP_ACC_FIELDS count idx...`，直接 return

**优化后字节码**（4 条指令）：
```
0052  92 OP_GET_LOCAL  1          ; sum
0055  92 OP_GET_LOCAL  8          ; s（仅 1 次）
0058  92 OP_ACC_FIELDS  count=4   ; 一次读取 4 个字段累加
0064  92 OP_ADD_FLOAT             ; sum + 结果
0065  92 OP_SET_LOCAL  1
0068  92 OP_POP
```

**收益**：热路径 13 条 → 4 条指令，4 次重复压栈对象 → 1 次，3 次 `ADD_FLOAT` 消除。

**修改文件**：
- `src/include/leno_vm.h` — 添加 `OP_ACC_FIELDS` 枚举
- `src/vm/vminc/vm_run.inc` — 添加跳转表条目
- `src/vm/vminc/op_struct.inc` — 添加 VM 实现
- `src/codegen/codegen_expr.c` — `collect_acc_fields` + `try_emit_acc_fields` + `gen_binary` 集成
- `src/debug.c` — opcode 名称表 + disassemble

## ✅ 附带修复：复合赋值 float 类型特化

**问题**：`sum += float_expr` 原来总是用 `OP_ADD`（通用加法），未走 `OP_ADD_FLOAT` 特化路径。
同理 `-=`, `*=`, `/=` 也有此问题。

**根因**：`gen_compound_assign` 中只有 `is_int_op` 判断，缺少 `is_float_op`。

**修复**（`codegen_stmt.c` → `gen_compound_assign`）：
```c
int is_int_op = (var_type == TYPE_INT && value_type == TYPE_INT);
int is_float_op = (var_type == TYPE_FLOAT && value_type == TYPE_FLOAT);

case TOK_PLUSEQ:
    if (is_int_op)       emit_byte(gen, OP_ADD_INT, ...);
    else if (is_float_op) emit_byte(gen, OP_ADD_FLOAT, ...);
    else                 emit_byte(gen, OP_ADD, ...);
```
同理修复 `TOK_MINUSEQ`、`TOK_STAREQ`、`TOK_SLASHEQ`。

## ✅ 已完成：方案 6 — `OP_CMPJMP_LL_INT` / `OP_CMPJMP_LG_INT`（比较+条件跳转合并）

**状态**：已实现、已测试、已合入

**问题**：循环边界检查产生大量"比较 + 跳转 + POP"序列

```
OP_GET_LOCAL 2          ; si (3 bytes)
OP_GET_GLOBAL 0          ; NS (3 bytes)
OP_GE_INT                ; 比较结果压栈 (1 byte)
OP_JUMP_IF_FALSE 12      ; peek 不弹 (5 bytes)
OP_POP                   ; 手动弹掉 bool (1 byte)
```
= 13 字节，2 次 push + 2 次 pop + 5 次 fetch/decode + 1 次跳转

**统计**：`benchIndex`、`benchHit`、`benchHitSingle` 各 1 处，3,000,000 次循环每次都执行。

**方案**：新增两个融合指令，直接从 local/global 读值比较并跳转，完全不碰栈

- `OP_CMPJMP_LL_INT cmp_op(1) slot_a(2) slot_b(2) offset(4)` — 两个 local int 比较
- `OP_CMPJMP_LG_INT cmp_op(1) slot(2) global_idx(2) offset(4)` — local int 与 global int 比较
- `cmp_op`：0=EQ, 1=NE, 2=LT, 3=GT, 4=LE, 5=GE
- 语义：比较结果为 **false** 时跳转（与 `JUMP_IF_FALSE` 一致）

**VM 实现**（`op_jump.inc`）：
```c
OPCODE(OP_CMPJMP_LG_INT) {
    frame = &vm.frames[vm.frame_cnt - 1];
    uint8_t cmp_op = READ_BYTE();
    uint16_t slot = READ_SHORT();
    uint16_t global_idx = READ_SHORT();
    int32_t offset = READ_INT32();

    int64_t a = val_as_int(frame->locals[slot]);
    int64_t b = val_as_int(vm.globals[global_idx]);

    int result = 0;
    switch (cmp_op) {
        case 0: result = (a == b); break;  // EQ
        case 1: result = (a != b); break;  // NE
        case 2: result = (a <  b); break;  // LT
        case 3: result = (a >  b); break;  // GT
        case 4: result = (a <= b); break;  // LE
        case 5: result = (a >= b); break;  // GE
    }
    if (!result) frame->ip += offset;
    DISPATCH;
}
```

**Codegen 触发**（`codegen_stmt.c` → `gen_if`）：
在 `gen_if` 的普通条件路径中，调用 `try_emit_cmpjmp` 检测以下模式：
1. 条件是 `AST_BINOP` 且是比较运算符（`>=`、`<`、`==` 等）
2. 两个操作数都是 `AST_VAR` 且类型为 `TYPE_INT`
3. 操作数来源组合：local-local → `OP_CMPJMP_LL_INT`；local-global → `OP_CMPJMP_LG_INT`；
   global-local → 反转比较符 + `OP_CMPJMP_LG_INT`
4. 满足条件则直接发射融合指令，跳过 `gen_expr + JUMP_IF_FALSE + POP` 序列
5. 同时消除 then/else 分支的 `OP_POP`（因为融合指令不碰栈）

**优化后字节码**（benchIndex 热循环）：
```
0069   93 OP_INC_LOCAL_NOPUSH  slot=2           ; si++
0072   94 OP_CMPJMP_LG_INT     GE local=2 global=0 off=11  ; si >= NS ? false→跳过
0082   95 OP_CONST             4 (0)             ; si = 0
0085   95 OP_SET_LOCAL_POP     2
0088   94 OP_JUMP              0 (to 93)
0093   90 OP_FOR_LOOP          ...
```

**收益**：热路径 6 条指令（GET_LOCAL + GET_GLOBAL + GE_INT + JUMP_IF_FALSE + POP + POP）→ 1 条 `OP_CMPJMP_LG_INT`，
2 次 push + 2 次 pop → 0，5 次 fetch/decode → 1。benchIndex 字节码 153→149 bytes。

**修改文件**：
- `src/include/leno_vm.h` — 添加 `OP_CMPJMP_LL_INT`、`OP_CMPJMP_LG_INT` 枚举
- `src/vm/vminc/vm_run.inc` — 添加跳转表条目
- `src/vm/vminc/op_jump.inc` — 添加 VM 实现
- `src/codegen/codegen_emit.c` — 添加 `emit_cmpjmp_ll_int`、`emit_cmpjmp_lg_int` 函数
- `src/codegen/codegen.h` — 声明
- `src/codegen/codegen_stmt.c` — `try_emit_cmpjmp` peephole 优化 + `gen_if` 集成

## ✅ 已完成：方案 8 — `OP_GET_FIELD_FAST`（struct 字段快速访问）

**状态**：已实现、已测试、已合入

**问题**：`OP_GET_FIELD` 的 struct 路径在热路径中开销过大：
1. `vm_stack_pop` — 弹出对象
2. `val_is_obj` 检查 — 1 次分支
3. `val_as_obj(obj_val)->type == OBJ_STRUCT` 检查 — 1 次分支
4. `field_idx >= def->field_count` 边界检查 — 1 次分支
5. `struct_get_field(obj, field_idx)` — 内部再做 1 次边界检查
6. `vm_stack_push` — 压入结果
7. 前面还有 `OP_GET_LOCAL` 或 `OP_GET_GLOBAL` 指令分发开销

当对象是 local 变量时，前缀的 `OP_GET_LOCAL` + 上述全部检查共 2 次指令分发 + 4 次分支 + 2 次栈操作。

**方案**：新增 `OP_GET_FIELD_FAST local_slot(2) field_idx(1)`（4 字节），在 Codegen 阶段当满足以下条件时发射：
- `AST_FIELD_ACCESS` 的 `field_index >= 0`（编译期确定）
- 对象表达式是 `AST_VAR` 且引用是 `SYM_LOCAL`/`SYM_PARAM`
- 对象类型已知是 struct（非 cstruct）

VM 侧直接从 `frame->locals[slot]` 读取对象指针，跳过栈弹出/类型检查/边界检查，直接做 `obj->field_values[field_idx]` 并压栈。1 次指令分发 + 0 次分支 + 1 次栈写入。

**析构函数兼容性**：析构通过 `OP_DTOR_LOCAL` 独立处理，与字段访问路径完全正交，不受影响。

**AST 级前置优化**：与方案 6 一致，在 Codegen 阶段从 AST 直接判断条件，不回看已生成的字节码，避免窥孔优化的历史 Bug（参见 `peephole-optimization-postmortem.md`）。

**Codegen 位置**：`codegen_expr.c` 的 `AST_FIELD_ACCESS` case 中，在 clib 检查之后、通用 `gen_expr + OP_GET_FIELD` 路径之前。

**VM 实现**（`op_struct.inc`）：
```c
OPCODE(OP_GET_FIELD_FAST) {
    frame = &vm.frames[vm.frame_cnt - 1];
    uint16_t slot = READ_SHORT();
    uint8_t field_idx = READ_BYTE();
    Value obj_val = frame->locals[slot];
    ObjStruct* obj = (ObjStruct*)val_as_obj(obj_val);
    vm_stack_push(&vm, obj->field_values[field_idx]);
    DISPATCH;
}
```

**影响范围**：所有通过 `obj.field` 语法访问 struct 字段且 obj 是 local 变量的场景。包括：
- 光线追踪 Phase A 中的 `s.cx`、`s.cy` 等独立字段访问（`s.cx + s.cy + s.cz + s.r` 链式加法走 `OP_ACC_FIELDS`）
- Phase B 中的 `h.hit`、`h.t` 访问
- 结构体方法内的 `self.field` 访问（通过 `__self_field__` 走 `OP_GET_FIELD`，不变）
- 所有用户代码中的 `localVar.field` 模式
