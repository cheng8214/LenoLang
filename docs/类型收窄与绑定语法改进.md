# 类型守卫收窄与 `=>` 绑定语法改进文档

> 本文档基于实际编译运行验证，记录 `is` 类型收窄与 `=>` 绑定语法在**泛型容器取值**场景下的类型语义、已知边界行为与最佳实践。
> 所有结论均由 `examples/type类型/` 下的测试文件实测验证，非推测。

## 一、核心语义：泛型收窄决定取出元素的类型

**用户提出并验证过的关键论断：**

> 收窄成裸 `Array` / `Dict` 取出元素是 `any` —— 这是**正常**行为。
> 只有收窄成带泛型参数的 `Array[int]`、`Dict[string, int]` 这种，取出来的元素才是**带类型**的。

这个论断**正确**，且是理解整个收窄体系的基础：

| 收窄目标类型 | 取出元素/值的类型 | 是否能直接使用 |
|-------------|------------------|--------------|
| `Array`（裸） | `any` | ❌ 需再收窄或强转 |
| `Array[int]` | `int` | ✅ 可直接算术 |
| `Dict`（裸） | `any` | ❌ 需再收窄或强转 |
| `Dict[string, int]` | `int` | ✅ 可直接算术 |

```leno
// 裸 Array：arr[0] 是 any，需再收窄
if x is Array => arr {
    var first = arr[0]      // first 是 any
    if first is int {
        return first        // 收窄传导到变量 first
    }
}

// Array[int]：arr[0] 直接是 int，可算术
if x is Array[int] => arr {
    return arr[0] + 1       // ✅ 无需再收窄
}

// 裸 Dict：d["a"] 是 any，需再收窄
if x is Dict => d {
    var v = d["a"]          // v 是 any
    if v is int {
        return v
    }
}

// Dict[string,int]：d["a"] 直接是 int，可算术
if x is Dict[string, int] => d {
    return d["a"] + 1       // ✅ 无需再收窄
}
```

### 泛型收窄是运行时元素类型检查

验证发现：`x is Array[int]` 的收窄是**运行时检查数组的每个元素**是否为 `int`。

```leno
var int_arr = [10, 20, 30]        // 全是 int
var mixed_arr = [10, "hi", 3.14]  // 混有非 int

if int_arr is Array[int] { }      // ✅ true
if mixed_arr is Array[int] { }    // ❌ false（即便第一个元素是 int）
```

因此：
- `Array[int]` 语义 = "**全是 int 的数组**"，混入其他类型即为 `false`。
- 想匹配"首个元素是 int"而不是"全部是 int"，应使用**元素级收窄**：
  ```leno
  if x is Array => arr {
      if arr[0] is int => n {   // 只关心第一个元素
          // ...
      }
  }
  ```

## 二、`=>` 绑定语法基础回顾

`if expr is Type => var { ... }` 一次性解决三个问题：**临时变量泄漏**、**重复求值**、**冗余 `as` 转换**。

```leno
if expr is Type => var {
    // var 在块内就是 Type，不需要 as
    // expr 只求值一次
    // var 只在 {} 内存在
}
```

核心特性（已实测）：
- ✅ `expr` **只求值一次**（有副作用也安全）
- ✅ `var` 类型**已收窄为 Type**
- ✅ `var` 作用域**仅在 then 块内**（else 与块外访问报"未定义变量"）
- ✅ 支持基本类型、`struct`、`enum`、`face`、泛型、`null`

## 三、已验证的边界行为与限制

以下行为均经 `examples/type类型/测试嵌套解包方案.leno` 实测确认。

### ✅ 限制 1：`and` 守卫链 + `=>` 绑定已修复

> **已修复**：`if x is Array => a and a[0] is float {}` 现在可以正常使用。
> 修改了 parser，将 `=>` 绑定检查从 `and/or` 循环之后移到之前，
> 并在 fallback 路径中保留 `guard_bind_var` 不清除。

```leno
// ✅ 现在支持：=> 绑定 + and 链
if x is Array => a and a[0] is float {
    // a 已绑定为 Array，a[0] 已收窄为 float
    return a[0] + 0.1
}
// ✅ 也支持 int、string 等
if x is Array => a and a[0] is int {
    return a[0] + 1
}
if x is Array => a and a[0] is string {
    return a[0] + "!"
}
```

### ✅ 限制 2：连续索引收窄已修复

> **已修复**：`a[0]["a"] is string` 的编译期收窄已实现。
> 修复方案：在守卫提取逻辑中识别嵌套 `AST_INDEX`（即 `expr->u.index.obj->kind == AST_INDEX`），
> 递归提取内层变量名和两层索引键，拼装为 `"inner][outer"` 格式存入 `index_key`。
> 守卫符号创建时用 `"%s[%s]"` 格式生成 `"a[0][key]"` 符号名。
> 类型推断时同样递归构造完整路径 `"a[0][key]"` 查找守卫符号。

```leno
// ✅ 现在支持：a[0]["a"] 连续索引收窄
if a is Array and a[0] is Dict and a[0]["a"] is string {
    return a[0]["a"]   // ✅ a[0]["a"] 已收窄为 string
}
// ✅ 也支持 int、float 等
if a is Array and a[0] is Dict and a[0]["val"] is int {
    return a[0]["val"] + 1   // ✅ 可算术
}
// ✅ 支持多连续索引 + and 链
if a is Array and a[0] is Dict and a[0]["a"] is int and a[0]["b"] is int {
    return a[0]["a"] + a[0]["b"]   // ✅ 两个都已收窄
}
// ✅ 支持连续索引 + => 绑定
if a is Array => arr and arr[0] is Dict and arr[0]["name"] is string {
    return arr[0]["name"]   // ✅ 已收窄
}
// ✅ 支持连续索引收窄传导到局部变量
if a is Array and a[0] is Dict and a[0]["val"] is int {
    var n = a[0]["val"]   // ✅ n 继承 int 类型
    return n + 100        // ✅ 可算术
}
```

### ✅ 限制 3：收窄信息传导到局部变量已修复

> **已修复**：索引守卫修复后，`var d = arr[0]` 时 `d` 能继承 `arr[0]` 的守卫类型（如 `Dict`），
> 因为类型推断在访问 `arr[0]` 时会查到守卫符号 `"arr[0]"` 并返回收窄后的类型。

```leno
// ✅ 现在支持：var d = arr[0] 后，d 继承守卫类型
if a is Array and a[0] is Dict {
    var d = a[0]   // ✅ d 的类型推断为 Dict（继承索引守卫）
    d["name"]      // ✅ 可访问（裸 Dict 返回 any，但可再收窄）
}
// ✅ 也支持 int 类型传导
if a is Array and a[0] is int {
    var n = a[0]   // n 继承 int 类型
    return n + 100  // ✅ 可算术
}
// ✅ 还支持嵌套：d["items"] is Array → var arr = d["items"]
if a is Dict and a["items"] is Array {
    var arr = a["items"]  // arr 继承 Array 类型
    if arr[0] is int {
        return arr[0] + 1  // ✅ arr[0] 有索引守卫
    }
}
```

### ✅ 限制 4：数组索引收窄已修复（原编译器 bug）

> **已修复**：`arr[0] is int` 和 `d["name"] is int` 的编译期收窄现已实现。
> 修复方案：在语义分析阶段从 `AST_TYPE_CHECK` 的 `expr` 中识别 `AST_INDEX` 节点，
> 提取变量名和索引键（数字、字符串、变量），在 then 块作用域中创建 `"arr[0]"` 格式的守卫符号。

```leno
// ✅ 现在支持：arr[0] is int 的编译期收窄已实现
if x is Array => arr {
    if arr[0] is int {
        return arr[0] + 1  // ✅ arr[0] 已收窄为 int，可算术
    }
}
// ✅ 也支持：d["name"] is string 的编译期收窄
if x is Dict => d {
    if d["name"] is string {
        return d["name"] + "!"  // ✅ d["name"] 已收窄为 string
    }
}
// ✅ 还支持：大索引、多个索引、and 短路
if x is Array => arr {
    if arr[10] is int {           // 大索引
        return arr[10] + 100
    }
    if arr[0] is int and arr[1] is int {  // and 短路多索引
        return arr[0] + arr[1]
    }
}
```

支持的索引类型：
| 索引形式 | 示例 | 守卫符号 |
|---------|------|---------|
| 数字常量 | `arr[0]`、`arr[10]` | `"arr[0]"`、`"arr[10]"` |
| 字符串常量 | `d["name"]` | `"d[name]"` |
| 变量索引 | `arr[i]` | `"arr[i]"` |

## 四、最佳实践

### 场景 1：逐步解包嵌套容器（数组→Dict→字段）

**唯一类型安全且能编译的写法是嵌套 `=>` 绑定**：

```leno
func extract(any a): string
{
    if a is Array => b
    {
        if b[0] is Dict => c
        {
            if c["a"] is string => d
            {
                return d
            }
        }
    }
    return "NOT_FOUND"
}
```

### 场景 2：嵌套太深时，拆小函数

```leno
func extract_first_a(Array arr): string
{
    if arr[0] is Dict => c
    {
        if c["a"] is string => d
        {
            return d
        }
    }
    return "NOT_FOUND"
}

func test(any a): string
{
    if a is Array => arr
    {
        return extract_first_a(arr)  // 类型已收窄为 Array
    }
    return "NOT_FOUND"
}
```

### 场景 3：单层容器 + 元素级收窄

```leno
// 关注"首个元素是 int"，而不是"全部是 int"
if x is Array => arr
{
    if arr[0] is int => n
    {
        return n + 1   // n 是 int
    }
}
```

### 场景 4：能提前确定元素类型时，直接用泛型收窄

```leno
// 数据源保证全是 int，直接用 Array[int] 一步到位
if x is Array[int] => arr
{
    return arr[0] + 1   // 无需再收窄
}
```

## 五、编译器改进记录

### 已修复

1. **✅ 数组索引收窄已实现**：`arr[0] is int` 和 `d["name"] is int` 的编译期收窄已修复。在语义分析的守卫提取逻辑中加入 `AST_INDEX` 识别，从索引表达式提取变量名和索引键字符串（支持数字、字符串、变量），在 then 块作用域中创建 `"arr[0]"` 格式的守卫符号。同时同步修改了 `and` 短路路径和类型推断逻辑。
2. **✅ 收窄信息传导到局部变量已修复**：索引守卫修复后，`var d = arr[0]` 能继承 `arr[0]` 的守卫类型。因为类型推断在访问 `arr[0]` 时会查到守卫符号 `"arr[0]"` 并返回收窄后的类型。
3. **✅ `and` 链 + `=>` 绑定已修复**：`if x is Array => a and a[0] is float {}` 现在可以正常使用。修改了 parser，将 `=>` 绑定检查从 `and/or` 循环之后移到之前，并在 fallback 路径中保留 `guard_bind_var`。在语义分析中添加预处理逻辑，在 `visit(cond)` 之前创建临时子作用域定义绑定变量，避免 `cond` 中的 `a[0]` 报未定义。
4. **✅ 连续索引收窄已实现**：`a[0]["key"] is Type` 的编译期收窄已实现。在守卫提取逻辑中识别嵌套 `AST_INDEX`（`expr->u.index.obj->kind == AST_INDEX`），递归提取内层变量名和两层索引键，拼装为 `"inner][outer"` 格式存入 `index_key`，守卫符号创建时生成 `"a[0][key]"` 格式。同时修改类型推断中的 `AST_INDEX` 查找逻辑，递归构造完整路径查找守卫符号。修改了三处代码：`visit_control.inc`（if 守卫提取）、`visit_expr.inc`（and 链短路守卫提取）、`semantic_type.c`（类型推断守卫查找）。

### 全部限制已修复

所有四个限制现已全部修复，类型守卫收窄体系已完整覆盖：
- ✅ 限制 1：`and` 守卫链 + `=>` 绑定
- ✅ 限制 2：连续索引 `a[0]["key"]` 收窄
- ✅ 限制 3：收窄信息传导到局部变量
- ✅ 限制 4：数组索引 `arr[0]` 收窄
