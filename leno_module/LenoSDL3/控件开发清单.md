# LenoSDL3 GUI 控件开发清单

> 目标：在现有 `Button / Label / Edit / Dialog` 基础上，补齐一套可用的 GUI 控件库。
> 当前控件范式：`set(Dict)` 初始化 → `process(Event)` 交互 → `render(Renderer)` 绘制 → `dispose()` 释放。
> 每个控件一个 `sdl_xxx.leno` 文件 + 工厂 `createXxx(Dict)`。

---

## 第 0 步：统一控件注册机制（基础设施，必须先做）

**动机**：`Window.run()` 主循环目前硬编码只认 `Button/Label/Edit`，每加一个控件都要改 `sdl_window.leno` 三处。引入 `face Widget` 后，新控件只需 `win.add(widget)` 一行即可自动参与事件与渲染。

- [x] 新增 `sdl_widget.leno`，定义 `face Widget { process(Event); render(Renderer); dispose() }`
- [x] `Button` / `Edit` 加 `impl Widget`
- [x] `Label` 补 `process(Event)` 空实现并加 `impl Widget`
- [x] `sdl_window.leno`：`Array[Widget] _widgets` + `add(Widget): Widget`；`run()` 内用单一循环统一 process/render；并行数组 `_runBtns/_runLbls/_runEdts` 合并为 `_runWidgets`
- [x] `SDL3.leno` 导出 `Widget` 类型
- [x] 回归测试：现有 `test_button / test_edit / test_label` 仍能编译运行

## 第 5 步：交互打磨（已完成，沉淀为基础设施）

> 这几项原不在清单内，是控件上线后暴露的边角问题，现已修复并固化为通用机制。

- [x] **滚动条鼠标交互** —— ListBox / ComboBox 原本滚轮能用、鼠标点不动；现已补齐
      "点击轨道跳转 / 拖拽滑块" 两条交互路径（`_sb_geom` / `_in_vscroll` / `_in_thumb`）。
- [x] **滚轮命中判定** —— 修复「滑第一个列表，下面也跟着滑」：新增 `wheelMouseX/Y()`
      （滚轮事件读 `mouse_x/y` 而非 Motion 的 `x/y`，纠正坐标错位）+ 各控件 `contains()` 命中守卫。
- [x] **弹层事件捕获区** —— 修复 ComboBox 弹层覆盖下层控件时事件穿透：`sdl_core.leno`
      新增 `setPopupCapture/clearPopupCapture/inPopupCapture`，`sdl_window.leno` 每帧渲染前
      清空，`renderPopup` 登记后下层控件自动忽略该区域。Menu/下拉等可复用此机制。

## 第 6 步：布局系统（已完成）

> 痛点：此前所有控件都用窗口绝对坐标摆放，调整一个就得手动算其它所有坐标。
> 方案：给 `Widget` 接口新增 `get_w()/get_h()/set_pos()/set_size()` 四个方法并在全部 11 个控件实现，
> 布局容器据此自动排版。因为尺寸/位置访问走统一接口，**未来新增的 TabControl/Menu/Table 天然可被布局容纳，
> 不需要布局本身做任何修改**——这正是“不影响后面扩展”的地基。

- [x] **HBox 水平布局** —— `win.addHBox({x,y,w,h,spacing,padX,padY})`
- [x] **VBox 垂直布局** —— `win.addVBox({...})`
- [x] **AnchorBox 锚点布局** —— `win.addAnchorBox({...})`，子控件按 `left/top/right/bottom/centerX/centerY` 钉位
- [x] **Widget 接口扩展** —— `get_w/get_h/set_pos/set_size`，11 个控件全部实现
- [x] **工厂与导出** —— `SDL3.createHBox/VBox/AnchorBox` 及 `win.addHBox/VBox/AnchorBox`

**子控件约定（与 Panel 一致）**：用 `SDL3.createXxx(...)` 创建子控件（不注册进窗口），
再用 `容器.add(child, opts)` 挂入；只把布局容器本身通过 `win.addXxx` 注册。
`opts` 支持：`expand`（占满主轴剩余空间）、`align`（0 起始 / 1 居中 / 2 结束 / 3 撑满交叉轴）、
`left/top/right/bottom/centerX/centerY/w/h`（仅 AnchorBox）。

**已知限制**：嵌套在布局里的 `ComboBox`，其展开弹层仍按旧逻辑绘制，不会自动浮到最上层
（弹层 overlay 走 `Window._combos` 第二遍绘制，嵌套布局的 ComboBox 不在其中）。
如需此能力，后续可让布局递归转发 `renderPopup`，或把 ComboBox 直接挂在窗口下。
