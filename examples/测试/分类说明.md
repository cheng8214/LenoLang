# 测试目录分类说明

本目录下的 95 个文件（含一个无扩展名的 `cs4_test` 并发测试文件）原本全部平铺，
彼此通过 `import` 相对路径耦合。现按用途拆分为 12 个子目录，便于维护与查找。

## import 路径约定

- Leno 的 `import` 路径**相对于导入文件自身所在目录**解析，支持 `../` 上级路径。
- 跨子目录引用统一写成 `../<分类>/<文件>.leno`（例如 `模块/main.leno` 引用
  `C结构FFI/cs2.leno` 写作 `import "../C结构FFI/cs2.leno"`）。
- 同子目录内的引用保持为裸文件名（如 `别名alias/` 内 `alias_renderer2.leno` 引用
  `alias_renderer.leno`）。
- 引用项目根目录外的库（如 `lib/SDL3.leno`、`leno_module/...`）使用
  `../../../lib/SDL3.leno`（因文件已在 `测试/<分类>/` 下，需多上一级）。

## 重构说明

- 移动使用 `git mv`，git 会识别为 rename 以保留历史。
- 31 处 `import` 路径已随目录调整统一重写；全量编译验证无"模块未找到/加载失败"类错误。
- 多数 `repro_*` / `test_*` 文件是**预期会报错**的缺陷复现用例，其报错属于内容层（语义/类型），
  并非 import 路径问题，无需修复即可作为回归用例保留。

## 已知遗留

- `main.leno` 调用 `cs2.test()` 报"模块 'cs2' 中没有方法 'test'"——属测试自身与模块不同步，
  非分类引入的问题。
- `repro_dialog_exact.leno` 复现 SDL3 `RenderCallback`/`EventHandler` 别名在 `use` 后不可见，
  属预期复现内容。
