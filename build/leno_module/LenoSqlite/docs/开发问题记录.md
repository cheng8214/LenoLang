# LenoSqlite 开发过程问题记录

> 在编写 LenoSqlite 封装过程中发现的 Leno 语言/编译器问题，供后续改进参考。

## 1. `defer` 语法不存在 — 已修复友好提示

**状态:** ✅ 已修复（编译器提示改进）

**问题描述:**
编写封装时自然地使用了 `defer { stmt.finalize() }` 语法（Go/Zig 风格），但 Leno 不支持 `defer`。

**修复前编译器表现:**
```
[未定义变量] 第 398 行第 1 列: 未定义的变量: defer
```
编译器把 `defer` 当作未定义变量，而不是给出清晰的 "defer 语法不支持" 提示。

**修复后编译器表现:**
```
[语法错误] 第 2 行第 1 列: 不支持的关键字 'defer'，请使用 try-finally 或手动调用清理函数
```

**修复内容:**
- 文件: `src/parser/parser.c` — `parse_statement` 的 `default` 分支中，检测 `TOK_IDENT` 是否为 `defer`，给出针对性提示。

**当前替代方案:**
```leno
// 替代 defer { stmt.finalize() }
Statement stmt = prepare(sql)
int rc = stmt.forEach(cb)
stmt.finalize()  // 手动清理
```

## 2. `export use` 语法不支持 — 已修复友好提示

**状态:** ✅ 已修复（编译器提示改进）

**问题描述:**
尝试用 `export use core.(sqlite3, ResultCode)` 重新导出子模块符号，编译报错：
```
[语法错误] export 后面期望 var、const、func、struct、cstruct、clib、enum 或 alias
```

**修复后编译器表现:**
```
[语法错误] 第 2 行第 8 列: 'use' 已自带重导出语义，不需要 'export'，请直接使用 'use module.Type'
```

**修复内容:**
- 文件: `src/parser/parser_module.c` — `parse_export_stmt` 中新增 `TOK_USE` 检测，提示 `use` 已自带重导出。

**说明:**
`use` 本身就带有 re-export 语义（enum/struct 类型自动 re-export），不需要 `export use`。但文档中对 `use` 的 re-export 行为说明不够充分，初学者容易混淆。

## 3. `use` 不能导入 `const` 常量 — 已有友好提示

**状态:** ✅ 已有友好提示（无需改动）

**问题描述:**
`use core.SQLITE_STATIC` 报错：
```
[语义错误] use 语句不能导入常量 'SQLITE_STATIC'，请使用 core.SQLITE_STATIC 访问
```

**说明:**
`use` 只能 re-export enum/struct/clib 类型，不能 re-export `const` 常量。常量需要用 `export var` 转发：
```leno
export var SQLITE_STATIC = core.SQLITE_STATIC
```

编译器已有良好的错误提示，验证通过。

## 5. Dict 值类型不匹配 — 设计如此，非 Bug

**状态:** ℹ️ 设计决策（非 Bug）

**问题描述:**
```leno
Dict row = {}
row[colName] = stmt.column_double(i)  // float → int? 报错
```
编译器报类型不匹配，期望 int，实际 float。

**说明:**
空字典 `{}` 的值类型为未指定（NULL），第一次赋值时会锁定值类型。这是**设计决策**，不是 Bug。第一次赋值后，字典值类型就被固定为该值的类型。

**替代方案:**
```leno
// 方案1: 用 _str() 统一转为字符串
row[colName] = _str(stmt.column_double(i))

// 方案2: 显式声明类型
Dict[string, float] row = {}
```

## 6. 错误消息中文乱码（编码问题） — PowerShell 终端问题

**状态:** ℹ️ 终端问题（非编译器问题）

**问题描述:**
在 PowerShell 中编译时，中文错误消息显示为乱码：
```
=== 鍙戠幇 11 涓敊璇?===
[璇法閿欒] ... 绗?9 琛岀 1 鍒? ...
```

**说明:**
编译器输出的 UTF-8 编码是正确的（重定向到文件后用 UTF-8 读取完全正常）。乱码纯粹是 PowerShell 终端默认使用 GBK codepage 显示 UTF-8 文本导致的。

**解决方法:**
- 使用 `cmd /c` 执行（cmd 已有 `SetConsoleOutputCP(CP_UTF8)` 调用）
- 或在 PowerShell 中先执行 `chcp 65001` 切换到 UTF-8 codepage
- 或将输出重定向到文件后用 UTF-8 编码读取

## 7. `as Ptr` 对整数常量的转换 — 已修复

**状态:** ✅ 已修复（VM 改进）

**问题描述:**
SQLite C API 中 `SQLITE_TRANSIENT` 是 `(sqlite3_destructor_type)-1`，即 `(void*)-1`。尝试用 `SQLITE_TRANSIENT as Ptr` 转换失败，返回 null。

**修复前:**
`as Ptr` 只能匹配已经是 FFI 指针对象的值，遇到整数时返回 null。

**修复后:**
`as Ptr` 现在支持整数到指针的自动转换。整数会被包装为 `ObjFFIPointer` 对象。
```leno
var p = (-1) as Ptr  // 现在可以正常工作
```

**修复内容:**
- 文件: `src/vm/vminc/op_as_cast.inc` — `TYPE_PTR` case 中增加对 `int`/`float` 值的处理，将其包装为 `ObjFFIPointer`。

## 8. 不支持单引号字符串 `'...'` — 已修复

**状态:** ✅ 已修复（语法支持）

**问题描述:**
Leno 不支持单引号字符串 `'name'`，只支持双引号字符串 `"name"`。

**修复前编译器表现:**
```
[语法错误] 第 4 行第 16 列: 意外的字符 ''' (重复 3 次)
[语法错误] 第 4 行第 16 列: 期望表达式
[语法错误] 第 4 行第 17 列: 声明语句后期望换行或 ';'，但同一行出现标识符
[语法错误] 第 4 行第 21 列: 意外的字符 ''' (重复 3 次)
```
编译器把单引号 `'` 当作 "意外的字符"，连续产生 8 个错误（4 种），用户体验差。

**修复后:**
单引号字符串 `'...'` 现在与双引号 `"..."` 完全等价，支持所有转义序列（包括 `\'`）。
```leno
var s1 = 'hello'           // 正常
var s2 = 'it\'s a test'    // 转义单引号
var s3 = 'say "hello"'    // 单引号中双引号不需转义
```

**修复内容:**
- 文件: `src/lexer.c` — `read_string` 增加 `char quote` 参数，新增 `case '\'':` 分支。
- 文件: `src/parser/parser_utils.c` — `process_escape_sequences` 增加 `case '\'':` 转义处理。

**根因分析:**
lexer.c 的 `lexer_next()` switch 语句中只有 `case '"':` 分支处理双引号字符串，没有 `case '\'':` 分支。单引号走到 `default` 分支报 "意外的字符"。

## 9. 示例文件路径写入问题

**状态:** 🐛 工具问题（非语言问题）
