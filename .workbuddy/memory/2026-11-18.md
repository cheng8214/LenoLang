# 2026-11-18

## 修复：内生模块名被同名 .leno 静默遮蔽（编译器 bug）

**症状**：Android 示例目录里放了一个测试文件 `ffi.leno`，`import ffi` 被解析成**那个本地文件**，
于是 `ffi.load(...)` 编译成「GETGLOBAL + INDEX + CALL」通用路径，运行期在那一行报
`函数未定义`（位置/文案与真实原因毫无关系）。桌面 `leno_vm.exe` 跑同一份 `.lenb` 也复现
⇒ 与 Android 无关、与 CPU 无关，只取决于**源文件目录里有没有同名文件**。

**定位过程（值得记住的）**：
- 桌面复现不了 → 是因为 `ffi.leno` 只在 `android/app/assets/` 里；把同一文件拷到 `/tmp` 就正常。
- `--debug-out` 看字节码是决定性的：正常版是 `OP_LOAD_NATIVE_MODULE + OP_MODULE_CALL`，
  坏版本是 `OP_INIT_LENOMODULE + OP_INDEX + OP_CALL` —— 两种形态一眼区分。
- 清 `.lenocache` 无效（不是缓存），因为同目录的 `ffi.leno` 每次都会重新命中。

**修法（三处）**：
1. `src/package/package_resolve.c` `package_resolve_import_spec()`：裸名命中
   `native_is_builtin_module()` 直接返回 -1（不解析成文件）⇒ 解析器/扫描器/加载器共用一份规则。
2. `src/parser/parser_module.c` `parse_import_stmt()`：内置裸名跳过解析，并用
   `package_resolve_module_file()` 探针把**被忽略的文件**报成警告。
3. 新 `WARN_BUILTIN_MODULE_SHADOWED`（`leno_types.h` + `error.c` 标签）。
   逃生写法：`import "ffi.leno"`（带扩展名 ⇒ 走文件路径规则）。

**验证**：`assert/run_tests.leno` 646/646 通过；`leno_gui` 抽查 --check 通过；
Android 上 `ffi_top.lenb`/`ffi_main.lenb` 均正确（`hypot(3.0,4.0)=5.0`，退出码 0）。

## Android 能力实测：11 探针 / 100 断言全通过

**产物**：`android/app/assets/c1..c11*.leno`（探针）、`android/run_probes.sh`（一键跑+汇总）、
`docs/Android能力实测_2026-11-18.md`（报告）。

**结论**：逻辑层齐了 —— 语言核心 / 文件 / JSON / 正则 / 时间随机 / 真并行线程 + 协程 /
DNS+TCP+手写 HTTP GET / SQLite / FFI / 多文件模块 / 纯 .leno 标准库（Crypto 的 sha256 过已知答案），
设备上全部可用。缺的是 UI 与系统集成（剪贴板/通知/传感器/权限），需 JNI 反射桥或 SDL3 自绘。

**本轮修的两个运行时缺陷（任何 app 都绕不过）**：
- `_script()` 在嵌入模式返回 null：它只从 `argv` 取，而 JNI 调 `lenolang_run_lenb()` 没有 argv。
  ⇒ 新增 `leno_set_script_path()`，在 `lenolang_run_lenb()` 入口自动写入。
- `_tmpdir()` 返回 `/tmp`：POSIX 分支无 TMPDIR 时硬编码，Android 沙箱不可写。
  ⇒ 新增 `leno_set_data_dir()`，宿主 `onCreate` 传 `getFilesDir()`；
  JNI 侧暴露 `setDataDir(String)`。
  两者定义在 sys.c（core 清单，两个构建都链），声明在 `include/leno_vm_runtime.h`。

**SQLite 的关键事实**：Android 只允许 dlopen `public.libraries.txt` 里的库（API30 共 28 个），
系统 `libsqlite.so` 不在其中，按名/按绝对路径都被 namespace 拒绝。
⇒ 必须自带 `libsqlite3.so`：`android/app/jniLibs/<abi>/`（NDK 编 amalgamation，-Os，约 860KB/ABI），
构建脚本以 **STORED** 方式写入 `lib/<abi>/`（压缩则安装器不解成可加载库）。实测 3.46.1 建库/查询/重开全通。

**三个踩过的坑（写进报告了）**：
1. `set_timeout` 单位是**毫秒**（写 8 变成 8ms，表现为"对端没数据"）。
2. `regexs` 参数顺序是 `(文本, 模式)`，且不支持 `{}` 量词（只有 `* + ?`）。
3. 导入标准库用**库文件名**：`import "Crypto"`（不是 `LenoCrypto`）；`LenoResult` 目录下是 `Result.leno`。

**其它**：`ffi.load` 找不到库时**抛错**而非返回 null，探针里必须 try/catch 兜住；
`probe_data` 不能写进 `assets/`（中文名让 aapt2 打包直接失败）⇒ 探针统一落 `_tmpdir()`。

## 20:00 模块库按平台分目录 + `_os()` 能分辨 Android

用户问"你编的 sqlite3.so 放模块里了吗"→ 没有，当时只在 APK 的 `jniLibs/`。
用户提议"模块里增加 win/linux/android 目录"⇒ 采纳，但落地时发现**光搬文件不够**，必须同时补两处 C 层能力。

**新布局**（`build/leno_module/LenoSqlite/lib/`）：
`win/sqlite3.dll`、`linux/sqlite3.so`、`android/<abi>/libsqlite3.so`，另加 `README.md` 写换版命令。

**必须配套的两个改动（否则分目录根本加载不到）**：
1. `src/module/ffi/ffi.c`：搜索路径原来会把传入路径**剥成纯文件名**（`filename = last_sep + 1`）
   ⇒ `win/sqlite3.dll` 永远命中不了。新增 2a-2 步（mod_dir + 完整相对路径），
   **并且 2c 那轮（遍历所有已加载模块目录）也要加** —— 实测真正救场的是 2c：
   编译期内联的模块 `current_module_frame->module->source_path` 可能为空 ⇒ mod_dir 取不到 ⇒ 2a/2a-2/2b 全跳过。
2. `src/module/sys/sys.c` 的 `native_os`：新增 `#ifdef __ANDROID__ → "android"`，**必须排在 `__linux__` 之前**
   （bionic 同时定义 `__linux__`）。这是**行为变更**：原来 `_os()=="linux"` 在 Android 上成立，现在不成立
   （`LenoSys.isLinux()` 因此返回 false，语义正确）。要"POSIX 就行"必须写 `linux or android`。

**同一坑的两个连带项**：
- `leno.toml` 的 `[native-libs.sqlite3]` 路径要跟着改成 `lib/win/...`、`lib/linux/...`，
  否则 `run_all_tests.leno` 的 `missing_lib()` 判定缺库后**静默 SKIP** 整个模块（汇总只多一个 SKIP，极易漏看）。
  Android **不写进 toml**：一个平台键只能指一个路径，装不下两个 ABI。
- `build_android.sh` 改为优先从 `lib/android/<abi>/` 取库（jniLibs 降为兜底），
  `android/app/jniLibs/*/*.so` 已加 gitignore（原本也没入库，只是 status 里碍眼）。

**两个工具链坑（会浪费大量时间）**：
- `leno.exe`（编译器）和 `leno_vm.exe` **各自内嵌一份 VM**。改 `src/` 下 C 代码必须 `build.sh` + `build_vm.sh` 都跑。
  本轮只重编 VM，导致"VM 跑 .lenb 正常、leno.exe 跑 .leno 报库加载失败"，一度误判为 ffi.c 改错了。
- `run_all_tests.leno` 必须用 **`leno.exe`** 跑：它内部用 `_executable()` 拼子进程命令，
  用 VM 当 runner 会全线 `exit=1`（看着像所有模块都崩了）。
- `adb logcat -c` 是**异步**的：清完立刻回读会读到旧数据。探针脚本要 `-c` → 等 0.5s → 回读验证；
  反过来固定 sleep 等探针跑完又会漏计（c6_net 10s 只抓到 3 条，实际 6 条）。现改为轮询等"结果:"行。

**新增探针 `c12_module_sqlite.leno`**：走模块 API（不是裸 FFI）验证 —— 这正是 c8 掩盖过的事实：
c8 直连 `libsqlite3.so` 能过，但**模块自己在 Android 上加载不了库**。14 项断言（建表/绑定/多行读/NULL 语义/事务回滚/坏 SQL 文案/关库重开）。

**写模块探针会撞的三条语法限制**：被导入模块不传递自己的 import；`Result[T].unwrap()` 静态类型是 `T`
（泛型不单态化）⇒ 取句柄改用 `db.prepare()`；回调参数要写 `func(sqlite3.Statement st)`。

**最终回归**：桌面 `assert/run_tests` 646/646、模块 `run_all_tests` 52/52、设备探针 114/114（12 个探针）。
设备实测 `_os()=android`、`libversion()=3.46.1`（APK 那份），桌面 3.53.4（模块 dll）。
