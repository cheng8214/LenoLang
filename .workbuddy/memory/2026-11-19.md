**工具链踩坑（值得记住）**
1. 代理只放行 `codeload.github.com`，`github.com/.../releases/download` 一律 502；
   所以拿不到 release 资产（含预生成的 mbedtls 文件），只能按 tag/branch 取源码。
2. 没有 ninja：`pip install ninja` 失败（清华源反而不通，官方 PyPI 通）。
   → 用 mingw32-make，但**必须复制到无空格无括号路径**（/c/android-toolchain/bin/make.exe），
   否则 CMake 通过 sh 调用时报 `syntax error near unexpected token '('`。
3. mbedTLS 3.6：`framework/` 子模块必需；`GEN_FILES=ON` 必需（git 检出无生成文件）；
   要 Perl + Python + jsonschema + jinja2；CMake 会自己挑 Python ⇒ 必须
   `-DPython3_EXECUTABLE=` 钉死，否则 build 阶段才报 ModuleNotFoundError。
4. 剪枝必须保留：libpng `scripts/`、libwebp `cmake/`、freetype `builds/`、curl `docs/`+`scripts/`
   （`add_subdirectory(scripts)` 无条件）。剪完再 configure 一次是必须的。
5. `SRC_SO="$(ls ...)"` 在 `set -e` 下会让脚本**静默退出**（退出码还是 0），
   表现是只打印到 `[2/2]` 就没了 → 改成先赋路径再 `[ -f ]` 判断。

**SDL3 在 Android 的硬限制（重要结论）**
- `ffi.load("libSDL3.so")` → `SDL_Init` 必失败：`Failed, there is no JavaVM`。
  SDL 的 VM 是在**它自己的 JNI_OnLoad** 里缓存的，而 dlopen 不触发该钩子。
- **不要**手动调它的 JNI_OnLoad：里面 `FindClass("org/libsdl/app/SDLActivity")` 找不到
  就抛 pending exception，ART `AssertNoPendingException` 直接 abort（有 tombstone）。
- 所以只验「不碰窗口」的链路：surface 创建/填充、SDL3_image PNG 编解码、
  SDL_ttf 用 NotoSansCJK 渲染中文 → 全部通过。开窗要改成 SDL 官方 android-project 形态。

**LenoWeb 的 CA 方案（新能力）**
Android 没有 native 可用的系统 CA（在 Java KeyStore 里），裸编 libcurl 也没有默认 CA 路径。
→ `web_curl_core.caBundle()` 把 `/system/etc/security/cacerts/*.0`（每文件就是 PEM）
拼成 bundle 落 `_tmpdir()`（实测 741KB），`HttpClient.init()` 自动设 `CURLOPT_CAINFO`。
好处：证书跟系统更新走，不随包塞会过期的 cacert.pem。

**新增探针** c13_qr(10) / c14_sdl3(10) / c15_audio(3) / c16_curl(7)。
