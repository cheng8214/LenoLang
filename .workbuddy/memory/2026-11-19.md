# 2026-11-19

## 07:30 模块原生库全部改为 win/linux/android 分目录

用户：`既然sqlite都改成win liunx androws这个文件夹格式，你看其它我模块也改成这种模式`。
把 SQLite 的布局推广到全部有原生库的模块（4 个）。

**最终布局**（`build/leno_module/<Mod>/lib/`）
- LenoMusic：`win/miniaudio.dll`、`linux/miniaudio.so`
- LenoQR：`win/quirc.dll`、`linux/quirc.so`
- LenoSDL3：`win/` 6 个 dll、`linux/` 6 个 so（含 webp 三件套）
- LenoWeb：`win/libcurl-x64.dll`、`linux/libcurl.so`
- LenoSqlite：已有（多一个 android/<abi>/）
全部用 `git mv`，历史保留。

**关键改动（不只是搬文件）**
1. 每个模块的 loader 改为**平台子目录优先 → 裸文件名兜底**。
   兜底那路是给打包产物用的：`package_install.c` 的 `collector_add` 只取 basename，
   复制到 exe 同目录时子目录前缀被剥掉。
2. LenoSDL3 有 4 个独立加载点（core / font / image / filedialog），原来**各写一份**
   `dirs.script_dir()+"/../SDL3"` —— 现在统一调 `sdl_core` 导出的
   `libDir()` / `libPath(base)` / `libBare(base)`，不再各写。
   `sdl_filedialog` 为此新增 `import "sdl_core.leno" as core`（它原来只 import sdl_window）。
3. LenoMusic 的 `find_dll()` 重写：候选根目录数组（缓存/CWD/lib/../../lib/入口脚本目录）
   × 每个根下先试子目录再试裸名。导出 `rel_path()` / `bare_name()` 供诊断。
4. 构建脚本输出路径跟着改：`LenoMusic/src/build_so.sh|build_dll.bat`、
   `LenoQR/src/build_so.sh|build_dll.bat`（QR 的 so 脚本新增 `OUT_DIR` 变量，macOS 复用）。
5. `LenoMusic/src/miniaudio.dll|.so` **从版本库删除**（与 lib/ 里那两份完全重复，
   1.6MB）。统一口径：`src/` 只放源码。

**踩到的两个既有 bug（本次顺手修）**
- `LenoSDL3/leno.toml` 原来有三个 `mac = "lib/SDL3.so"` 键，而那个 .so 是 **Linux ELF**
  ⇒ `mac` 键只检查"文件存在"，是**假通过**（打包能过、运行时 dlopen 必失败）。
  已删除 mac 键并在 toml/README 写明恢复条件。
- `run_all_tests.leno` 的 `missing_lib()`：
  (a) 判 `_os() == "mac"`，而 `native_os()` 返回 `"macos"` ⇒ 该分支从未生效；
  (b) 只判 `ends_with(".so")`，漏掉 soname 形态 `libwebp.so.7` / `libcurl.so.4`
      ⇒ "声明了但文件不在"检测不到，表现为整个模块被**静默 SKIP**。
  已修为 `macos` + `strings.has(q, ".so.")`。
  (c) 另加 `_os()=="android"` 分支（我 11-18 改了 `_os()` 返回 "android"，这里没跟）。
